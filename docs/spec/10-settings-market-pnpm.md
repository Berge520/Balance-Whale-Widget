  - **⚠️ 不给「取消安装」**（有意取舍）：取消会让 pnpm 处于半途（profile 已建快照但 `node_modules` 可能写一半），回滚风险高于收益。只解决「不知道在装」的**可见性**问题；真要中止仍可关掉 dsh 或等它跑完，界面明确提示「请不要关掉本页：pnpm 由宿主进程托管，关页不会中断，但也看不到结果」。
  - **⚠️ `cmd /s /c` 这条线上的参数引号必须走 `quoteCmdArg`，不能用 POSIX 式引号**（真实 bug：症状「更新失败（退出码 1）」+ 日志 `'\"D:\nodejs\npm.cmd\"' 不是内部或外部命令`）：`spawnCmd` 在 Windows 下走 `spawn(cmd.exe, ['/d','/s','/c', 整串])`。`/s` 的语义是「**先给整串包一层引号，再剥掉最外层那对**」：若再按 POSIX 习惯给**每个**参数包 `"`，外层补的那对与内层错配，命令名被吃成 `dejs\npm.cmd\"`。**npm / dsh 全系列调用当场全废**（安装、更新、卸载、`dsh` 启动都走这条线）。内层改用 cmd 的 `""` 转义**同样失败**，因为 `/s` 的剥离发生在转义解析之前。**规则**：只给**真正含空格或 shell 元字符**的参数加引号，参数内引号用 cmd 的 `""`；裸参数（`install` / `--prefix` / 包名）一律不加。`dsh-dump.test.mjs` 有回归钉住（「拼出来必须与实测能跑通的形态逐字相等」）。**排查提示**：与项目 / Node / npm 版本无关，见到「不是内部或外部命令」且命令名首尾带畸形引号，先查这里。
  - **⚠️ 装 / 卸插件必须走 pnpm，不能走 npm**（真实 bug，症状「更新失败（退出码 1）」+ `npm error code ERESOLVE`）：`installPluginPkg` / `uninstallPluginPkg` 原先调 `runNpm`（`npm install --prefix <profile> <spec>`），而 profile 里装着 `@openviking/dsh-memory-plugin@0.3.2`，声明 3 个 peer（`@deepseek-ai/dsh-llm` / `dsh-mcp-client` / `dsh-skill-filesystem`）：**这三个 peer 由全局 dsh 提供，不在 profile 自己的 `node_modules` 里**。npm 只认当前目录的树，判 peer 不满足，`while resolving` 阶段直接 ERESOLVE 中止，**信息还误导**（看不出真因是 peer）。`--legacy-peer-deps` 实测能 exit 0，但**会连带升降大量无关包**（含 `undici`、`@antfu/install-pkg` 降级）：为一个包装上而搅乱整个 profile，不可接受。
    - **正解是改走 pnpm**（用户决策：走官方通道）：dsh 本就由 pnpm 维护 profile 依赖树：`node_modules/.modules.yaml` 里记着 `hoistPattern` / `layoutVersion` / `virtualStoreDir` / `storeDir` / `packageManager: pnpm@11.25.0`，`pnpm-workspace.yaml` / `pnpm-lock.yaml` 也都在。**用 npm 改这棵树，pnpm 下次同步就会改回去**。pnpm 语义也不同：`pnpm-workspace.yaml` 写着 **`autoInstallPeers: false`**，故对上面那组 peer **只报 `[WARN] Issues with peer dependencies found` 而不中止**。**本机实测**（真目录 + 真 registry）：`pnpm add --dir <profile> --registry=… --reporter=append-only dshmarket` → **exit 0**，之后 dependencies / `dsh.profile.bundles` / `allowBuilds` / `pnpm-lock.yaml` **全部未变**（`Packages: +4 -12` 是 hoisted 模式的位置重排，非版本变更）。**故无需任何补丁参数**。
    - **⚠️ 找不到 pnpm 要明确报错，不能偷偷退回 npm**：新增 `resolvePnpm` / `findPnpm`（`state.pnpmCache` 缓存，`configure()` 换 Node 目录时清空）。候选目录 = Node 目录 + PATH + `%APPDATA%\npm` + `%LOCALAPPDATA%\pnpm\bin` + `commonDirs()` —— pnpm 通常是全局包（`npm i -g pnpm`），全局 bin 常常不在 PATH。**为什么不用 `node.npm exec pnpm`**：Electron 里 `process.execPath` 是 uTools 自己，取不到 npm 前缀，这条兜底是死的。找不到就回文案「未找到 pnpm：profile 的依赖树由 pnpm 维护，装插件必须用它。请先安装（npm i -g pnpm）或在设置页指定 Node.js 目录」：**静默退回 npm 只是把 ERESOLVE 换个地方再报一次**。
    - **`pnpmArgs(dir)` 的两个要点**：① **必加 `--reporter=append-only`**：默认 TTY 报告器打满进度条与光标控制字符，ANSI 清掉后残渣仍会把关键报错挤出视野；② **绝不能加 `--ignore-scripts`**：`github:` / tarball 来源的插件靠 `prepare` 在安装时构建，忽略脚本等于**装出一个空壳**；该不该跑构建交给 pnpm 自己的 `allowBuilds` 白名单裁决（拦下时 pnpm 给出要写进 `pnpm-workspace.yaml` 的 key，正是 `parseAllowBuilds` 解读的那条链路）。
    - **⚠️ pnpm 输出也是「失败也要读」**：与 npm 一样，失败详情在 stdout/stderr 里，`runPnpm` 的 `bindOutput` 照旧 `pushLog`，进度回显链路不变。
    - `dsh-dump.test.mjs` 补回归：`pnpmArgs` 的 `--dir`/`--reporter` 顺序与「未配镜像不凭空加 `--registry`」、不带任何 `--ignore*`、`installPluginPkg` / `uninstallPluginPkg` 拒非法 profile / spec（**进不了命令行**）、`resolvePnpm` 找不到时返回空串**不降级**。
  - **⚠️ pnpm 退出码 0 ≠ 真的升级了：必须比「回读到的实装版本」**（真实 bug，症状是界面显示「已更新 dshmarket（v1.48.0 → v1.48.0）」）：

    - **⚠️ 换回 npm 也升不上去**：这道白名单由 dsh 侧维护，pnpm 只是执行者，**不是 pnpm 引入的限制**。所以「改用 pnpm」并不解决升级，只解决 ERESOLVE（见上一条）。
    - **⚠️ 后续修的两处：判据不能拿 `supply-chain` 字样当证据 + 文案必须给出可照抄的版本号**（用户报第二条，症状是文案里出现字面量「目标版本」，照抄不了）：
