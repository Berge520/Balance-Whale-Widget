- **「dsh 插件市场」卡片**（「开发者」Tab，夹在「DeepSeek Harness（dsh）」与「dsh 用量统计」之间）：**整卡默认收起**（`devFolds.market`，同 `toggleDevCard`），**首次展开才抓目录**（`devStatsLoaded.market` 只置一次）。卡片头摘要（`marketSummary`）三段：未读「点击展开浏览」、有结果「N 个插件（M 已装）」、失败「加载失败」。它是**该 Tab 唯一会联网的卡**（其余卡 `hint` 都写「不发网络请求 / 只读本地」），故**显式声明会联网**、**展开不自动抓**（要再点「加载目录」），避免静默外发。
  - **目录来源是并发竞速，不是串行回退链**（`buildSources` + `loadCatalog`，`dsh-market.js`）：**所有锁定来源同时发请求，首个拿到合格目录的胜出，其余立刻 `AbortController.abort()`**。竞速的由来：官方源 `plugins.json` 体积大、body 下载慢（瓶颈是传输），腾讯 / npmmirror 的 `dsh-plugin-catalog` tarball 约 1MB、下得快（同一份目录）；串行回退要等最慢的前一个失败，首屏干等。
    - **来源构成**（`buildSources`，顺序即数组序）：`custom`（填了 URL 就恒参与，`dshMarketUrl`）→ `mirror`（用户选的 registry，`dshMarketRegistry`）→ `official`（`dshMarketOfficial`，**默认 false**）。**⚠️ 官方源默认关**：实测常连不上（`UND_ERR_CONNECT_TIMEOUT`），开着只白占一条卡住的连接；保留开关是「官方最权威」的诉求真实。两个都关时 `loadCatalog` **明确报「没有可用的目录来源」**，不静默回空目录。
    - **四个配置项都进 `config`**（按「配置四处同步铁律」）：`dshMarketUrl`（`normMarketUrl` 只留 `http(s)://` 开头、截 300 字，非法值回空串 = 不参与）、`dshMarketMirror`（是否允许镜像源，**默认 true**）、`dshMarketRegistry`（registry 地址，`normRegistry` 校验，空 = 内置默认 `MIRROR_REGISTRIES[0]`）、`dshMarketOfficial`（**默认 false**）。设置页 `cfg` 字段与 `applyConfig` 回填都要有，否则宿主读到 `undefined` 走默认链、改了不生效。
    - **失败隔离靠 `done()`**：单源网络错 / 内容不合格 / 校验失败只是**它自己出局**（`failures` 记一条）；`AbortError` **不算失败**（「别人先赢了」）；全部出局才 `ok:false`，`error` 拼上每条链路的失败原因。
    - **兜底超时 `FETCH_TIMEOUT_MS = 15s`**：竞速下**只用于取消最慢的源**（快源早返回了），不是一次加载的墙钟时长。**⚠️ 镜像源不吃这个总时限**（`loadCatalog` 的全局计时器跳过 `kind === 'mirror'`）：目录包 1–3MB，镜像抖动到几十 KB/s 时链路仍在传字节，15s 一刀切会把下载杀掉、目录退回（默认关的）官方源（上游 b766e2a 的真实事故）。
    - **镜像 tarball 用「停滞看门狗」而不是总时长**（`fetchHeaders` + `readBodyStall`）：头部（响应开始）仍用 `FETCH_TIMEOUT_MS = 15s`（头是一次性到达的，固定预算合适）；体只对**连续 `BODY_STALL_TIMEOUT_MS = 15s` 没有新字节**判死，另加 `BODY_TOTAL_CEILING_MS = 10min` 整体上限与 `MAX_TAR_BYTES = 256MB` 体积上限兜底 —— 前者防「每 15s 吐一个字节」的坏镜像永远拖住，后者硬性封住内存。**不能对体继续用同一个 `AbortSignal.timeout`**，那会把仍在推进的响应一起掐断；竞速输家的清理仍由 `raceSignal` 监听完成。
  - **镜像源可选 + 可测速**（`MIRROR_REGISTRIES` / `dshMarketPing`）：内置三个（`npmmirror`（阿里，最快，**默认**）/ 腾讯云 / npm 官方 registry），三者**内容同源**。设置页「目录来源」区给单选 + 「测速」：`dshMarketPing` **只打 registry 元数据（`/<pkg>/latest`）、不下载 tarball**，`Promise.all` 并发、按延迟升序回 `{id,url,label,ms,ok,error,version}`。**⚠️ 测速不改配置**：改哪个源由用户点「用最快的」（`dshMarketUseFastest` 写 `cfg.dshMarketRegistry` 后重载）显式决定；华为云镜像元数据**不给 `dist.tarball`**，故不在内置列表。
  - **镜像链路要解 tarball，零依赖手写**：registry 元数据（`<registry>/dsh-plugin-catalog/latest`）→ `dist.tarball` → `zlib.gunzipSync` → 手写 tar 头解析（`untarOne`，512 字节块、只找 `package/plugins.json`）。**tarball 地址必须校验 `^https?://`**（元数据可能把我们带去任意第三方主机）。
  - **条件请求按来源分别存校验器**（`mem.validators[src.key]`，`key` 形如 `url:<地址>` / `npm:<registry>/<包名>`）：目录很大却**每天才刷新一次**，不带校验器就每天全量重下。`condGet` 先 `if-none-match`、退化 `if-modified-since`（**二者只发一个**：同时发时某些代理会挑它不喜欢的那条，反而判错），304 复用内存体。**⚠️ 校验器只在该来源真返回新体时更新**：304 响应里没有 etag，无条件覆盖会抹掉有效校验器，之后再也发不出条件请求。校验器**必须按来源隔离**，否则「官方源 etag」被拿去问镜像源，必然 200 全量重下。（镜像链路走 tarball 无 304，304 只发生在 `custom` / `official` 两条 JSON 链路。）
  - **⚠️ `install` 字段才是权威安装命令，不是 `npm` 字段**（`normPlugin` / `parseInstallSpec` / `specKindOf` / `specNeedsBuild`）：实测目录**全部**带 `install`（统一格式 `dsh plugin --profile <p> add <spec>`），`npm` 字段**近半数**为 `null`。这类条目**不是装不了**，只是 spec 换了形态：去尾词、按需剥 shell 引号后落三种：**裸包名** / **`github:owner/repo`** / **`"https://…/x.tgz"`**。故 `normPlugin` 输出 `spec` / `specKind`（`npm` / `github` / `tarball` / 空=认不出）/ `needsBuild`（`github` 与 `tarball` 为 true）三件套，**已删早先的 `installable: !!npm`**：那判据把近一半目录判死。条目 `name` 可带 `#子包` 后缀（如 `dsh-gungnir#dsh-plugin`），**展示用 `name`、安装一律用 `spec`**。`description` 中英双语、某侧可能缺，`screenshots` 少数条目才有。
  - **⚠️「需构建」是 pnpm 的安全机制，不是我们的 bug**（`specNeedsBuild` + `parseAllowBuilds`）：`github:` / tarball 来源靠 `prepare` 脚本安装时构建，**pnpm 默认拦截**，报 `ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED`，要求把 key 写进 `<profile>/pnpm-workspace.yaml` → `allowBuilds`。**key 带 commit hash（形如 `dsh-better-sidebar@git+https://github.com/o/r.git#1fcf43cc…`），安装前拿不到**，故注定先失败一次。界面据此给按钮 + 失败后引导：宿主用 `parseAllowBuilds` 从 pnpm 原文抠出 `{key, file}` 回传，卡片原样呈现、**明说「不替你自动放行」**（键写错 dsh 不报错，静默失效）。**⚠️ key 不是反引号包起来的**，是缩进两格的裸 yaml 行；`file` 必须优先取带路径那条（报错正文先出现的是裸名 `project's pnpm-workspace.yaml`）。
  - **筛选与排序全在前端做**（`filterPlugins`，**先筛后排**）：数千条走 IPC 逐次过滤代价太高，宿主一次把整份目录（含 `categories` 的**出现顺序**）交给前端本地过滤 + 排序。排序轴 `SORTS` = `downloads`（默认）/ `stars` / `added` / `name`。**`categories` 要补条目里出现但目录没给的分类**，否则那些条目筛不到。
  - **排序方向可切换，默认方向跟着轴走**（`SORTS` / `SORTS_DESC` / `desc`）：`SORTS` 各轴一律写成**升序原语**（数值 `a-b`、文本 `a.localeCompare(b)`），方向由 `desc` 外层取反，写死降序就没法表达「名称倒序 / 下载量升序」。`SORTS_DESC` 给默认方向（**数值 / 日期降序、名称升序**，即 `{stars:true, downloads:true, added:true, name:false}`），界面写 `sort: 'name', desc: false` 即「名称升序」，不必再维护 sort → desc 映射（两处必漂移）。**⚠️ `desc` 没给（undefined）才用默认，显式 `false` 必须被尊重**：`o.desc || SORTS_DESC[key]` 会把 `false` 顶掉（`false || true` → `true`），永远升不了序。再点当前轴 = 反向，**换轴 = 按新轴默认方向复位**（否则从「名称升序」切到「下载量」会变「下载量升序」）。方向是**读出来的事实**（`方向：降序`），非独立开关，免得「方向：降序」却没选中任何轴。
  - **关键词支持空格分词与 `-` 排除**（`matchKeyword`，前端 `dshMarketList` 同口径复刻）：空格分词后是**与**关系（每段都要命中，可跨字段：搜 `dsh usage` 能出 `dsh-usage`），`-词` 表示排除。**只有排除词也成立**（如 `-plugin`）：无正向条件，等于「全目录减去命中的」。**⚠️ 光一个 `-` 不算排除词**（用户可能只想打个连字符）：跳过，否则整份目录清空。比对前把 name / owner / descZh / descEn 拼成 haystack 再逐段 `indexOf`：拼接可能造成跨字段假命中，但不引入分隔符语义（存进配置的既是搜索串也是匹配规则），**接受，不加分隔符**。
  - **⚠️ 外链必须先过 http(s) 白名单**（`safeWebUrl`，`market-link.js`）：目录是第三方内容，条目的 `page` / `url` 谁都能写，而 `services.openExternal` 直通 `utools.shellOpenExternal` —— `file:` 会被原样交给系统壳（点一下等于打开本地路径），`javascript:` / `data:` 同理。判在**宿主**这一个出口上（覆盖面最大，含页面里用户输入的链接），前端 `openDoc` 只判空。
  - **目录不给主页时用安装 spec 反推源码入口**（`sourceWebUrl`，与上游 dsh-market `sourceWebUrl` 同口径）：`github:o/r#子包` → `https://github.com/o/r`、`git+https://host/o/r.git`、`git@host:o/r`（scp 写法）、`ssh://git@host:o/r`（端口是传输层的、不带进网页地址）统一成 https 仓库页；大小写保留，裸包名 / tarball / 本地路径一律回空。结果由**宿主 `normPlugin` 派生**成 `sourceWeb` 字段随目录下发，模板在「主页」缺失时渲染「源码」按钮。**⚠️ `..` 必须在 `new URL()` 之前拦**：解析器会把 `/o/../etc` 归一成 `/etc`，事后再查路径段永远查不到（单测钉住）。
  - **⚠️ 列表必须分页截断**（`DSH_MARKET_PAGE = 80`）：全量一次渲染会卡死，底部给「加载更多」。
  - **⚠️ 已装判定必须按 install spec 反查，前端与宿主同口径**（`matchInstalledBySpec` + `matchInstalled`，前端 `dshMarketInstalledBySpec` / `dshMarketHitOf`）：`npm` 为 null 的近半数条目没有 npm 名可对，但装完后 `dependencies` 里**会**有键（**npm 把 github spec 归一成 `owner/repo`、远端 tgz 归一成包名**）。故按 spec 归一出候选键再比（`github:o/r` → 加 `o/r`、`r`；URL → 末段去 `.tgz`/`.tar.gz` 与版本号；**`@scope/name` → 加去 scope 的 `name`**），**「spec 反查优先、npm 完整名优先去 scope 短名兜底」两层都要**。返回 `{key, depVersion}`（`key` 供卸载定位真实键名（`uninstallPluginPkg` 只认键名不认 spec））。**⚠️ 两种入参形状不能混用**：`matchInstalled` 吃 `installedMap` 的**记录表**（返回记录本身 `{inDeps, depVersion, …}`），`matchInstalledBySpec` / `matchDepByNpm` 吃 `installedDeps` 的**原始表**（`{键: 声明范围}`，返回 `{key, depVersion}`）：更新链路只有原始表，误用 `matchInstalled` 会让 `hit.depVersion` 恒 undefined（那位置是**裸字符串**），range 为空、state 全掉进 `unknown`（单测钉住）。**⚠️ 两边口径必须逐字一致**，否则「卡片说未装、宿主 dryRun 说已装」。
  - **⚠️ 「已装状态」读不到时不冒充未安装**（`filterPlugins` 的 `if (!installed) continue`）：profile 的 `package.json` 没读过时，`state` 过滤（已装 / 未安装）**把条目全部跳过**，而非把已装的标成「未安装」骗用户点安装；界面侧 `dshMarketList` 同样「拿不到 status 就跳过」，两处必须一致。`state: 'all'`（默认）不受影响。
  - **「已装」是两个来源的合成**（`installedMap`）：`profile/package.json` 的 `dependencies` 说「**装没装**」（npm 层面）、用户层 `cordis.patch.yml` 的条目说「**开没开**」（dsh 层面）。一个包可能装了但被 `disabled`，也可能在 patch 里但没装（写了不存在的 id），故两个都读。
  - **⚠️「装的是哪个版本」要另读 `node_modules`**（`installedVersions`，返回 `{ 目录名: version }`）：`dependencies` 存的是**声明范围**（`^0.5.11`），不是实装版本，检查更新必须用实装版本。**直读 `<profileDir>/node_modules/<name>/package.json` 即可，不必处理 `.pnpm` 或软链**：dsh 底层虽是 pnpm，但 `.modules.yaml` 里 `nodeLinker: hoisted`，包被**硬链接成实体目录**平铺在顶层；改 isolated 模式（顶层是软链）解引用后仍能读通。**按 `dependencies` 的键读取，不遍历整个 `node_modules`**（几百个传递依赖）。读不到的包**不编造**，调用方拿不到就退回范围判定。
