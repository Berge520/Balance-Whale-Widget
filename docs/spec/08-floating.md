## 八、悬浮窗页面（floating.css + floating-bubble.css + floating-page.js + floating-pages.js）

`floating.html` 只是薄壳（`<link>` 引 `floating.css` / `floating-bubble.css`，`<script src>` 依次 `bubble-render.js` → `offwork-core.js` → `floating-pages.js` → `floating-rings.js` → `floating-page.js`）。`floating-pages.js` 是气泡页队列的纯逻辑（IIFE 挂 `window.WhalePages`，不碰 DOM / 页面状态），`floating-rings.js` 是环形进度条的绘制与计时进度计算（IIFE 挂 `window.WhaleRings`，只对一个 svg 写属性、不算页面状态），两者单独成文件都是为了不让 `floating-page.js`（6269 行棘轮）继续膨胀。脚本为 IIFE + 幂等守卫 `window.__dshWhaleWidget`。资源相对路径 `./whale/...`。

- **共享气泡渲染器**：DOM 构建、`applyLines`、换图状态机 `setGifSrc`、字号自适应 `fitText`、gif 淡出计时的单一来源是 `src/bubble/bubble-render.js`（导出 `THEMES` / `BUBBLE_FONT` / `buildBubbleDom` / `createBubbleRenderer`）。悬浮窗不能用 ES module（file:// 硬约束）：`vite.config.js` 的 `buildBubbleRenderIife` 在 `closeBundle` 用 esbuild 打成 IIFE `dist/bubble-render.js`（不压缩、全局名 `window.BubbleRender`），`floating.html` 以普通 `<script>` 在 `floating-page.js` 前挂载；设置页直接 ESM import 同一源文件（`BubblePreview.vue`）：共享**源码**而非副本。渲染器不依赖页面状态：gif 失败文案与「气泡是否正开着」经 `gifFailLines` / `onGifError` 交页面；页面只做接线（`applyBubbleLines` / `fitBubbleText` / `resetBubbleFont`）与绑 click。三处副本由 `check-shared.mjs` 钉住：`BUBBLE_FONT` ↔ `.dshwv-label/amount/period/hint` 字号、`THEMES.default` ↔ `.dshwv-bubble` 变量默认值、`/ 1026` 除数 ↔ `--dshw-u`；气泡样式独立成 `floating-bubble.css`。

DOM：`.dshwv-root`（窗口内**居中**，四周留 `--whale-pad` 透明留白；贴左吸附时整体 `scaleX(-1)` 镜像）> `.dshwv-body`（Q 弹缩放）> `img.dshwv-img` + `.dshwv-bubble`（SVG + `.dshwv-gif` + `.dshwv-text` 三行）；`.dshwv-menu-btn` 三点按钮（穿透中加 `.dshwv-menu-btn-pass`）；`.dshwv-menu` **挂 body**（不在 root 内：全局透明度靠 CSS 变量同时作用于两者，不写内联 opacity）。`.dshwv-body` 内、`img` 之后还有两层装饰：`.dshwv-refresh-mask`（手动刷新的呼吸圈，`pointer-events:none`，挂 `.dshwv-refreshing` 时走 `box-shadow` 动画）与 `svg.dshwv-ring`（环形进度，`stroke-dashoffset` 控进度，专注/短休/长休由 JS 写 `--dshw-ring-color` 换色；计时未跑而下班倒计时开着且该显示它时，同一只圈改画当日工时进度 —— 剩余比例 = 1 − `dayProgress().pct`，配色沿用专注蓝，跨日班 / 非工作日 / 休息日拿不到进度、或已下班（`phase === 'after'`，进度恒 100%、只剩灰色轨道）时整只圈收起，计时进行或暂停时圈一律归计时）。

- 命中测试：鲸鱼图画到 610×610 canvas，`getImageData` 读 alpha>10（左镜像时 x 翻转）；据此决定拖拽/穿透/光标。
- 拖拽：pointerdown 在鲸鱼上 → 记 `screenX/Y` 与 `clientX/Y`，立即上报 `drag-begin`（宿主进入拖拽冻结态）；移动按 `目标窗口左上角 = screenX − clientX0`（拖拽中恒定）rAF 节流上报 `drag-move`；位移平方 <9 判点击（开气泡 + 刷新），否则松手上报 `drag-end`。**`dragLock` 开启时不累计位移、不上报 `drag-move`、禁用滚轮缩放**（位置与大小都固定），松手仍按点击处理，窗口不动。
- **拖拽期窗口尺寸缓存**（`dragWinSize`）：`drag-begin` 读一次 `getSize()`，拖拽期复用，`drag-end` 清空：原先 `dragMoveTo` 每帧 `win.getSize()` 是同步 IPC 往返，而 `dragFrozen` 下尺寸恒不变。配套：工作区缓存 `dragWin`（跨屏才重算）、位置相同则跳过 `setPosition`。
- **拖拽位置只保留一条最简链路**：页面 rAF 节流上报（每帧最多一发），宿主在 `whale:drag-move` 处理器里**直接同步 `setPosition`**。**两个已推翻的方案，别再回头**：(a)「发一帧 → 等 ack → 再发下一帧」严格背压：直线甩动中间帧可丢，但**画圈时相邻帧方向完全不同、无可合并**，吞吐被单个往返锁死；(b) 宿主侧 `setTimeout` 自驱循环（~120Hz）apply 最新目标，与页面 rAF 形成**第二条节奏源**，`dragTarget` 为空也空转 tick，更卡。结论：任何「第二条节奏源」或「逐帧回执」都会变差。
- **拖拽冻结缩放**：拖拽期滚轮缩放与实时缩放一律冻结（滚轮在 `drag.active` 时 return，`sendLiveScale` 短路；宿主 `applyScaleToWindow` 见 `dragFrozen` 只记目标值）。修的是「拖动时不由自主变大、大小描述却不变」：拖拽难免带出滚轮（触控板尤易误触），而实时缩放**不写存储、不回推配置**，一触发就「窗口真变大、`scale` 停在旧值」。被冻结的最后一个目标在 `drag-end` 补做并持久化，**顺序排在吸附之后**（补做会写 anchor、推配置，颠倒会覆盖吸附结果）。
- **拖拽期间屏蔽 `contextmenu`**：左键按住时再按右键，系统**照样**派发 `contextmenu`，菜单弹出会打断拖拽。故 `contextmenu` 在 `drag.active` 时 `preventDefault` + `stopPropagation` 后返回；**只挡「正在拖」**，拖拽结束后右键唤菜单完全保留（透明留白区本不在鲸鱼命中范围）。
- 滚轮缩放：指针命中鲸鱼且非菜单内时 `wheel`（`passive:false` + `preventDefault`）按 `deltaY` 符号 **±1 档**（先 `snapNum(curScale)` 归到当前档，档位 1–`SCALE_STEPS`）改大小，`setScale(target,true,false)` 实时预览、停手 260ms 后 `setScale(target,false,true)` 持久化（参数是档位，不是倍率）；到 1/`SCALE_STEPS` 边界不再变更；`dragLock` 开启或拖拽中直接 return 不缩放。
- Q 弹：body `scaleY(.88) scaleX(1.05)`，origin `50% 100%`，`transform .22s cubic-bezier(.34,1.56,.64,1)`。
- 音效：press=Ya1/D1、release=Ya2/D2；按住松手与短按（press 末尾提前 100ms 接 release）两节奏；vol=0 静音；`new Audio` 失败静默。音色可切「自定义」（`soundSet:'custom'`）：音源来自宿主推送的 base64 data URL（`whale:init.sounds` / `whale:sounds`），**以按压音为准**，缺失时整体回退小黄鸭；释放音可缺（`releaseAudio = null`，松手静音）。
