## 八、悬浮窗页面（续）· 汉堡菜单与窗口行为

- 汉堡菜单**分组**（`menuGroup(key, title, onExpand)` 构建；**默认全折叠，每次打开重置**：不落盘、不记忆，见 `toggleMenu`）：
  - **待办**（`todo`，默认收起）：`todoOn` 关着时整组 `display:none`（`pushInit` 也只给 `todo:null`）；打开时排在最前（`menuBox.appendChild(groupTodo.el)` 早于模型组）。挂件**只读 + 勾选**，增删改一律回设置页（窗口默认不可聚焦，不放输入框）。**只画未完成项**：本次菜单里刚勾掉的置灰留在原位（`todoJustDone`，`toggleMenu` 打开时清空），下次打开即消失 —— 回看 / 清理已完成交给设置页，否则清单越用越长、把待办挤出滚动区；全完成时空态写「待办都完成了，去设置页加新的」。每行 = `checkbox`（`whale:todo` 的 `op:'toggle'`）+ 文字 + 「专注 / 专注中」按钮（`op:'focus'`，仅 `focusOn` 且未完成时出现，再点即取消）；底部「管理待办」→ 关菜单 + `openSettings('focus')`。勾选只上报、不改本地状态，等宿主整份回推。
  - **模型**（`models`，默认收起）：切模型最高频，紧跟待办组（待办组关掉时它就是第一组）；只有内置 DeepSeek 时整组 `display:none`，行内容见「多厂商模型菜单」。
  - **外观与音效**（`look`，默认收起）：大小 / 音效 / 音量 / **透明度** / 气泡（+ 气泡设置）/ 报时 / 锁定。
  - **用量与峰谷**（`usage`，默认收起）：用量 / 峰谷 / **峰谷提醒**。主显示非 `deepseek` 时整组收起。
- **计时**（`timer`，默认收起）：**计时**（模式下拉 + 开始/暂停/继续）/ **读数**（剩余 / 已用 / 休息·暂停 + 重置，只在计时中 / 暂停时出现）/ **目标**（倒计时时/分/秒三段或定时刻，按模式二选一）/ **到点通知**（开关 + 停留档位）。留言与休息档**不在菜单里**（悬浮窗无好输入环境），只在设置页「提醒与通知」改；页面留本地副本供到点气泡与「休息 N 分钟」用，由 `applyConfig` 回推。
- **专注联动**（与待办组共用 `focusOn` / `todoOn`，两个开关**互不联动**）：① 计时气泡尾注由 `withFocusTail` 在 `focusOn` 时追加「 · 专注：<任务名>」（任务名截 8 字），关掉专注闭环后残留的 `focusId` 不再挂到气泡上；**休息轮（`timerIsBreak`）不挂尾注**——这一轮不在专注，挂着会让人以为休息也算专注；② 到点动作条第 3 个按钮 `timerTodoBtn`「完成这条」仅在 `focusOn && !timerIsBreak && todoFocusText()`（当前有专注项）时出现，点击发 `op:'toggle'` 勾掉该条并关气泡，顺序为 休息 N 分钟 / 再来一轮（休息轮为「继续专注」）/ 完成这条 / 知道了，其中「休息」与「完成这条」在休息轮都隐藏；③ 轮次上报在 `finishTimer()` 的 `reportFocusRound()`：`focusOn && !timerIsBreak && timerMode === 'down'` 才发 `whale:focus { minutes }`（分钟 = `Math.max(1, Math.round(timerArg/60))`；目标时长 ≤ 0 不记；**不足 1 分钟按 1 分钟计** —— 30 秒一轮也是一次「完成」，记 0 分钟会让「今日 N 轮 / 0 分钟」自相矛盾、柱状图上这一轮直接看不见）—— **不搭通知的顺风车**，通知被静音时统计照记；④ **只有一个「专注记录」开关**：早先拆成「专注记录 + 计时结束自动记录」两个，前者描述里就写着「计时结束后自动记一轮」，关掉后者后整条链路变成什么都不记，用户只会以为开了功能却坏了
- **dsh**（`dsh`，默认收起，标签就叫 `dsh`）：**整组始终创建，按「机器上有没有 dsh」显隐**：首帧 `display:none`，`whale:dsh` 快照回来后由 `dshRender` 按 `source`（`global`/`plugin`，已安装）或 `running`/`external`（运行中）判定，命中才显示。`error` **不算**命中（只给一行无从下手的报错）。早先按 `window.whale.dev` 创建，**打包版开发者模式默认关 → 正式 `.upx` 里整节消失**，故改掉。内容 = 启动 / 重启 / 结束 + 页面 + 状态 + 命令（「更新」按钮已移除，仍可从设置页触发）；展开该组时经 `onExpand` 探一次状态（首帧由初始化探测决定，开菜单不另探）。
  - 末行：**打开设置**（整宽，`whaleApi.openSettings()` → 宿主 `utools.showMainWindow()`）+ **隐藏挂件**（同排次要，`whaleApi.hideWidget()` → `whale:hide-widget` → 宿主 `destroyWidget()`；唤回用设置页「显示挂件」或快捷键）。
  - 菜单行数多时靠 `.dshwv-menu` 的 `max-height` + `overflow-y:auto` 在屏幕内滚动，不被屏幕边缘裁掉。
- **`saveCfg()` 是「白名单提交」**：菜单每次改动把上述字段整份上报，宿主 `patchConfig` 逐字段覆盖（`p.x !== undefined` 才写）。**页面只读、无编辑入口的字段也必须在 `saveCfg()` 原样带回**：漏带即用 `undefined` 抹掉设置页的值。已踩过：`notifyMailOn`/`timerMailOn`（只在设置页改）漏带，动一下音量就关掉邮件通知；`applyConfig` 负责回填本地副本。**新增 `config` 字段时同步检查 `saveCfg()`。**
- 菜单**宽度与标签列**（`floating.css`）：`.dshwv-menu` = **固定 `275px` 基准** + `max-width: min(320px, 92vw)` + `scrollbar-gutter: stable`。**不要再改回 `width: max-content`**：面板 `overflow-y:auto`，展开组越多越易出滚动条，滚动条吃掉内容宽后 `max-content` 再加宽补偿，逐组加宽直到撞 `max-width`。固定基准后宽度恒定；`min(320px, 92vw)` 防小尺寸挂件面板越过窗口边缘；`scrollbar-gutter: stable` 常驻槽位，避免出滚动条时抖动。`.dshwv-menu-label` 为 `min-width:50px` + `max-width:72px`（固定值会把「透明度」「点按依次播放」挤到换行或撑破行；`min-width` 保短标签纵向对齐，超出仍 `nowrap` 裁切）。**菜单不再有「组内嵌组」**
- **`min-width:0` 必须贯穿「组 → grid 体 → inner → 行」**（`.dshwv-group` / `.dshwv-group-body` / `.dshwv-group-inner` / `.dshwv-menu-row`）：四层默认 `min-width:auto`（不小于 min-content）。dsh 那几行最宽（三个按钮 + 长串 `npm exec …`），min-content 超过面板 275px，行**整体越出右缘**（只有 `overflow-y:auto`，横向拦不住）；漏一层，里层仍被长行顶开。补上后行宽回到面板宽，`.dshwv-dsh-state` / `.dshwv-dsh-cmd` 的 `text-overflow:ellipsis` 才生效（此前被越界掩盖）。
- 分组**展开/收起做高度过渡**：`.dshwv-group-body` 用 `display:grid` + `grid-template-rows: 0fr ↔ 1fr`（展开态 `.dshwv-group-open`）+ `overflow:hidden`，`padding` 同步过渡：可直接对 auto 内容做动画，不必先测高度。**前提是 grid 只能有一个子项**：行逐个 `appendChild` 进 `api.body`，直接放进 grid 每行各占一条轨道，`0fr` 只压得住第一行；`menuGroup()` 在 `bodyEl`（grid 外壳）里多包一层 `.dshwv-group-inner`，`api.body` 指向该 inner。**别再直接切 `bodyEl.style.display`**：高度瞬变，`positionMenu()` 重夹 `maxHeight` 时会跳。
- 「目标」行**拆成两个互斥子行**（`rowTimerDown` / `rowTimerAt`）：倒计时（时/分/秒三段 + 单位）与定时（`input[type=time]`）各占一行，由 `syncTimerMenu()` **只看 `timerMode`** 二选一（正计时/关闭时两行都收起）；原先同行靠 `display` 二选一，隐藏的仍占 flex 宽。**「重置」已统一挪到读数行**（`timerResetBtn` 只挂一处，三种模式共用，随读数行显隐），目标行里不再放按钮 —— 早先为绕开「同一 `button` 不能挂两行」复制过 `timerResetBtnAt`，正计时跑起来后菜单里因此没有任何清零入口。`syncTimerMenu()` 里**不要再用忙闲态（`timerBusy()`）参与判定**：曾写 `var down = idle && timerMode === 'down'`，而 `busy` 与 `idle` 互斥（`busy = running || paused`），计时中/暂停时 `down`/`at` 恒为 `false` → 两行同时露出，且兜底分支 `busy && (down || !at)` 化简即 `busy`，把倒计时的重置按钮塞进 `rowTimerAt`。
- 菜单控件都补 `title`（悬停提示，同 `aria-label` 文案）：`select`/滑块/按钮无可见 `<label>`，光靠同行 `span` 说不清；组标题按钮同带 `title`。
- 菜单的**可访问性语义**：`menuBox` 是 `role="dialog"` + `aria-modal="true"`（面板一开经 `whale:input-focus` 借走焦点，挂件本体不可交互，声明成模态才不会被辅助技术读进后面的挂件）。组标题按钮带 `aria-expanded`。**收起的分组必须给 `inner` 置 `inert`**：收起只把 grid 压成 `0fr` + `overflow:hidden`，控件仍在 DOM、能被 Tab 聚焦，焦点会送进看不见的输入框；`inert` 一次停掉整棵子树的聚焦与点击，比逐个 `tabindex="-1"` 稳妥（`apply()` 里有 `try` 兜底，老 Chromium 无此属性也不抛错）。`closeMenu()` 把焦点还给 `menuBtn`（**仅在 `menuBtnEnabled` 时**：按钮被设置页关掉时不可聚焦，`focus()` 是空操作），否则纯键盘关掉后焦点掉到 body，下次 Tab 得从头找。
- 「大小」行**只留滑块 + 档位读数**：滑块走整数档位 1–`SCALE_STEPS`（与设置页「外观」同一刻度），值经 `numToScale` 换算成倍率后推给宿主；精确输入去设置页。`SCALE_STEPS` 三处副本（`constants.js` / `floating-page.js` / `App.vue`）由 `scripts/check-shared.mjs` 校验。
- 透明度的菜单项是 5 档下拉（100/80/60/40/20%），与设置页连续滑块共用 `opacity` 字段，非档位值就近显示；改完走 `saveCfg()` 上报（宿主广播后再落 CSS）。
- **菜单展开方向与横向锚点**（`positionMenu`）：默认在按钮**上方**展开（不遮小鲸鱼），贴上边或装不下时改向**下方**（加 `.dshwv-menu-down` 反转入场动画，`transformOrigin` 换 top）。可用高度按 `min(space.up|down, --whale-pad) + 按钮到本体边缘距离` 算；`space` 由宿主随 `whale:init` / `whale:snapped` 下发。装不下时压 `max-height` 菜单内滚动，无 120px 硬下限。菜单**没打开直接 return**（模型行数变化等会无条件调到，白量一次高度 = 强制 layout）。**横向锚点是「挂件在屏幕上的内侧」而非「按钮左右边」**：菜单固定 275px 而四周留白只有 `--whale-pad`（200px），放不进纯留白区；贴按钮边盖住小鲸鱼；贴窗口边缘则菜单落在留白区一侧，只压本体靠外窄条。选**哪条**边缘的判据必须是 `flipped`（宿主按 `anchor.hAnchor` 推出「挂件贴工作区左侧」，随 `whale:init` / `whale:snapped` 下发，见 `preload/lib/widget.js` 的 `flippedOf`）——贴左时左边留白已在屏幕外，故菜单贴窗口**右**边缘（屏幕内侧），反之贴左，即 `menuOnRight = flipped`。**不能用按钮在窗口内的坐标判断**：那是窗口内部几何，拖到屏幕另一侧方向就反了（`getBoundingClientRect` 只反映镜像后的窗口内位置）。（`MENU_EDGE_GAP` = 4px，同垂直口径）
- **菜单开关**（`toggleMenu` / `closeMenu`）：打开先 `positionMenu()` 再置 `.dshwv-menu-open`（量到未夹取的自然高度），`scrollTop` 归零：小尺寸挂件菜单可滚动，不归零会停在上次位置；同时按需拉 dsh 状态（**dsh 分组收着时不拉**，不必白探 3080；展开才拉，见 `menuGroup` 的 `onExpand`）与模型懒加载（宿主侧节流）。窗口 `resize`（滚轮缩放时宿主连续 `setSize`）时菜单开着就重摆，否则与按钮错位。关闭：点菜单外**透明留白**只关菜单并**立即 `hoverAt()` 重算**穿透与按钮显隐（不重算要等下次 `pointermove`，这次点击被窗口吞掉、同位置再点也传不到下层应用）；点**鲸鱼本体**关菜单后照常当点击/拖拽（否则要点两下才能拖）。
- **多厂商模型菜单**（`renderModelsMenu`）：菜单里「外观」与「用量与峰谷」之间多一个**「模型」分组**，列出全部模型（含内置 DeepSeek，带「（内置）」标签），每行 = 主显示标记（`✓`）+ 名称 + 数值（余额型原币种金额、额度型「已用 x%」、出错「失败」、原因放进 `title`）；**点一行即设为挂件主显示**（`whaleApi.setMainModel(id)`），行尾另有「刷新全部」（`refreshModels(null, true)`）。只有内置 DeepSeek 时**整组隐藏**（`display:none`）。打开菜单发一次 `whaleApi.refreshModels(null, false)` 懒加载（宿主侧 5 分钟节流），宿主前后各推一次 `whale:models`，菜单先显示上次结果、不等网络
- **主显示切换后的挂件表现**（`handleModels`）：主显示非 `deepseek` 时——① 第 1 组随机台词改报该模型余额/额度（标题行 = 模型名 + 「余额」/「额度」，报时只属内置 DeepSeek）；额度型金额行显示**剩余百分比**、说明行「已用 x% · M-D HH:MM 重置」，余额型金额行显示原币种金额、说明行「~今日已用 x」（`~` 标明按余额差估算）；出错时金额行 `--`、说明行截断后的错误原因。② **「用量与峰谷」整组收起**（峰谷/预算/用量口径都属 DeepSeek 专属）。③ 切回 `deepseek` 立即 `refresh(true)` 要新余额（切走期间 `handleBalance` 放行）。币种前缀 `MODEL_MONEY_PREFIX` 在页面侧有**同内容兜底副本**（浮动页无 `require`，读不到宿主常量），两处同步改。
- **窗口透明度**（`applyOpacityCss`）：把 `opacityPct/100` 写成 `document.documentElement` 的 CSS 变量 `--dshw-opacity`，由 `.dshwv-root` 与 `.dshwv-menu.dshwv-menu-open` 消费（菜单关闭态仍是独立 `opacity:0`）。设置页拖动走 `whale:config {__live:true}`，宿主仅把 `{opacity}` 推回页面，不写存储、不回推设置页。**禁止窗口级 `setOpacity` 与内联 `opacity`**，原因见第三节第 16 条。
- **鼠标穿透**（`passThroughOn` / `passHoverActive`）：未接管时恒穿透，指针在鲸鱼或菜单按钮停留 `PASS_DWELL_MS`(1200ms) → `passTakeOver()`（`setIgnoreMouseEvents(false)` + 菜单按钮转实心常显）；接管后按常规命中测试，离开 UI 满 `PASS_RELEASE_MS`(700ms) → `passRelease()` 交回穿透（拖拽 / 菜单打开期间不交回）。穿透中且未接管时菜单按钮带 `dshwv-menu-btn-pass`（半透明 + 虚线环常显），切换穿透弹一次三行说明气泡（走 `showRemindBubble`，文案取设置页「文案」卡片（提醒文案分组）的 `passOn`/`passOff` 模板，红/绿沿用状态色，计时中跳过）：完整约束见第三节第 17 条。
