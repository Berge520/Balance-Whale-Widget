## 八、悬浮窗页面（续）· 汉堡菜单与窗口行为

> **v1.14.0（2026-11-01）现状**：挂件菜单已把「待办 / 专注 / 计时」合并为唯一的 **「专注」组**（键 `focus`），展开顺序固定为 **今日 → 当前 → 放弃确认 → 待办 → 计时 → 专注与待办设置**；组名按 `focusOn || todoOn` 在「专注 / 计时」间切换，折叠摘要优先显示当前任务与剩余时间。下面的 6–13 行保留合并前的分组细节作历史记录，当前实现以 `public/floating-page.js` 的 `groupFocus` 装配、`syncFocusGroupChrome`、`refreshMenuSummaries`、`updateTimerStatus` 与「接力气泡」一节为准。

- **余额条置顶常显**（`rowBalanceTop`）：菜单第一行，**不进任何折叠组** —— 余额是最高频的信息（「我还有多少钱」），藏在第二层要点两下才看得到。数值走 `mainAmountText()`（主显示换哪个模型就跟哪个），所以不参与「DeepSeek 专属行收起」；样式 `.dshwv-menu-toprow` 用一条分隔线与下面分组区分（它是信息，不是入口）。**标签与「复制」按钮文案都跟着主显示的「名分」走**（`mainAmountKind()` / `mainAmountLabel()` / `copyAmountLabel()`，在 `applyModelVisibility()` 里刷新）：余额型「余额 / 复制余额」、额度型「剩余额度 / 复制额度」、Codex「今日 token / 复制token」—— 写死「余额」时额度型会出现「余额 62%」这种自相矛盾的读法。**主显示不是内置 DeepSeek 时，标签前面再加模型名**（「Kimi 剩余额度」），否则「剩余额度 62%」看不出是哪一家（模型组默认收着，摘要只说「3 个」）；口径与气泡标题行 `defaultLabelText()` 同源。名字过长由 `.dshwv-menu-toprow .dshwv-menu-label` 的 132px 上限 + 省略号裁掉，`title` 给全名。复制后的临时态（已复制 / 复制失败）用 `copyBtnBusy` 挡住这层回写，1500ms 后同样按 `copyAmountLabel()` 复原。
- **穿透中的逃生行**（`rowPass` / `syncPassRow`）：鼠标穿透开着时挂件本体点不动，只能靠「在鲸鱼上停约 1 秒」临时接管才点得开菜单，菜单一关又得重来 —— 故在余额条下方常显一行「穿透中 · 关闭穿透」（`.dshwv-menu-passrow`，暖色，与普通设置行区分），一次点击即 `whaleApi.saveConfig({ passThrough: false })`。显隐只认「当前穿透是否开着」，**每次 `applyConfig` 都无条件刷一遍**（只在值变化的分支里设，重新落地配置时显隐会失真）。点击后**不做乐观隐藏**：保存失败时行若已消失，用户就失去这个逃生入口；改为置灰写「关闭中…」，等 `whale:config` 回推复原，另留 3s 兜底定时器防宿主异常时按钮永久卡住。
- **折叠态摘要**（`menuGroup` 的 `setSummary` / `refreshMenuSummaries`）：菜单收起时只有组名，什么值都看不到，故每组标题右侧挂一句当前值 —— 外观「4 档 · 100%」、余额与用量「今日 ¥1.48」、计时「剩 12:34 / 已用 12:34 / 暂停 12:34 / 休息 12:34 / 到点」，空闲时也写状态：关闭「默认 25 分」（来自设置页默认时长）、倒计时「25 分」、定时「定时 07:30」、正计时「正计时」、待办「3 项」、模型「3 个」。**专注轮数不再单独占一组**：合并组（专注 / 计时）在 `focusOn` 开着时把「 · 今日 N 轮」直接拼在计时状态后面（`setGroupSummary(groupTimer, 'timer', timerSum + focusSum)`），关着时只有计时状态。**今日用量拿不到时写「今日 --」而不是「今日 ¥0.00」**：`state.todayUsage` 为 `null`（实时·令牌口径下平台接口没给）时按 0 显示会把「没拿到」说成「今天没花钱」，与挂件第三行的「今日已用 --」口径也不一致。**计时摘要必须带状态前缀**：只写「12:34」时，正计时（已用）与倒计时（剩余）在同一位置显示同一个读数，含义完全相反；前缀取 `timerPaused` → `timerIsBreak` → `timerMode === 'up'` 的先后顺序判定（暂停 > 休息 > 已用 > 剩）。**展开时隐藏**（组内已有同一个数）。`refreshMenuSummaries()` 由 `render()`（余额 / 配置）、`updateTimerStatus()`（计时每秒，仅菜单开着时）、`renderTodoMenu()` / `renderModelsMenu()` / `onFocusStats` 调；内部用 `summaryCache` 挡重复写入（`textContent` 赋值会触发重排，1s 一次的计时刷新不该白做）。样式 `.dshwv-group-sum` 必须 `nowrap + ellipsis`（换行会把组头撑成两行，六个组一屏就装不下），上限 104px。
- 汉堡菜单**分组**（`menuGroup(key, title, onExpand)` 构建；**默认全折叠，每次打开重置**：不落盘、不记忆，见 `toggleMenu`）：
  - **待办**（`todo`，默认收起）：`todoOn` 关着时整组 `display:none`（`pushInit` 也只给 `todo:null`）；打开时排在最前（`menuBox.appendChild(groupTodo.el)` 早于计时组 / 模型组）。挂件里**可勾选、可快速添加**（`rowTodoAdd` 的输入框回车 / 点「添加」，`maxLength` 60 与宿主 `TODO_TEXT_MAX` 同值；输入框要键盘，靠 `toggleMenu` 的 `setInputFocus(true)` 借焦点），**改名 / 删除仍回设置页（清单底部另有「清除已完成」，一键 `clearDone`；没有已完成项时弹气泡说明，不静默）**。**只画未完成项**：本次菜单里刚勾掉的置灰留在原位（`todoJustDone`，`toggleMenu` 打开时清空），下次打开即消失 —— 回看 / 清理已完成交给设置页，否则清单越用越长、把待办挤出滚动区；空态一律走 `menuHint` / `menuHintAct` 这对唯一来源：全完成时一行「待办都完成了，去设置页加新的」；一条都没有时「还没有待办」+「点击下方输入框快速添加」+「勾选即完成；已完成的到设置页查看」。每行 = `checkbox`（`whale:todo` 的 `op:'toggle'`）+ 文字 + **到点提醒徽标（只读）**（`remindOn` 且 `remindAt > 0` 时出现，`.dshwv-todo-due`：`once` 当天写 `HH:MM`、非当天写 `M-D HH:MM`，`daily` / `weekdays` / `weekly` 一律 `HH:MM`；`once` 已过点转红（`.dshwv-todo-due-over`），`title` 给「到点提醒：<全称>」。挂件内不可编辑，改提醒去设置页「专注与待办」；到点只提醒，不自动开始计时）+ **今日轮数徽标**（`focusSummary.todayByTodo[it.id] > 0` 时显示「今日 N 轮」，`.dshwv-todo-today`；与下方累计 `rounds` 口径分开）+ **预估进度**（`it.est > 0` 时显示 `已完成/预估` 轮数，如 `2/3`，`.dshwv-todo-est`；没填预估不占位置）+ 「开始 / 进行中 / 专注中」按钮（仅 `focusOn` 且未完成时出现）—— **点「开始」= 设为当前专注 + 按这条自己的 `tm` / `mins` 启动计时**（`startTodoTimer`：`'up'` 正计时、`'down'` 倒计时 N 分钟；`''` 不计时则只设专注）；该条正在计时时显示「进行中」并禁用；「不计时」的条目再点一次取消专注；**已有计时在跑时点别的条目不再一律拒绝**：非休息轮且已专注 ≥1 分钟时在合并组内联确认「放弃本轮」，未满 1 分钟 / 休息轮直接切换（`requestTimerDiscard`，避免用户被一句「已有计时在进行」堵死）。`tm` / `mins` 由设置页每条待办的下拉配置，见 `05-ipc.md` 的 `whale:todo`；底部「管理待办」→ 关菜单 + `openSettings('focus')`。勾选只上报、不改本地状态，等宿主整份回推。**快速添加的两道前置判断**：① 回车提交带组字守卫（`e.isComposing` 或 `e.keyCode === 229` 一律不提交，与 `commitOnEnter` 同口径）—— 只判 `isComposing` 时，个别输入法确认候选词那一下会把半截词当成待办提交；② 条数达上限（`todoMax`，宿主随 `whale:init` 下发，源头仍是 `constants.js` 的 `TODO_MAX`）时先弹「待办已满」气泡并**保留输入内容** —— 宿主的 add 在满额时是静默丢弃的，页面不拦就会出现「输入框清空、清单没变」。
  - **专注 / 计时（合并组，复用 `timer` 组）**：**不再有独立的「专注」组** —— 复用原计时组 `groupTimer`，位置紧随待办、在模型之前（待办 → 开始 → 计时是同一条链；早先计时排在「外观」「用量」之后，从待办开始计时得先滚到底）。**标题随 `focusOn` 动态切换**：`renderFocusStats()` 开头 `groupTimer.setTitle(focusOn ? '专注' : '计时')`（`menuGroup` 新增的 `setTitle` 同时写组名与 `head.title`）—— 同一个组，开关开着叫「专注」，关着就只是「计时」。**执行区（这一轮）始终在**，与 `focusOn` 无关：计时模式下拉 + 开始/暂停/继续、放弃确认、快捷时长、读数与重置、目标行、双击提示（细节见下面「合并组的执行区」一节）。**统计区只在 `focusOn` 时出现**：`focusStatsEl` 由 `groupTimer.body.insertBefore(focusStatsEl, rowTimerFoot)` 插在设置行之前（组内顺序 = 计时执行行… → 专注统计 → 设置入口），三行：**今日**（设了每日目标时是「N / 目标 轮」+ 进度条，达成后带 🎉；没设目标时「N 轮 · N 分钟」）、**连续**「N 天」（`streak > 0` 才出现）、**近 N 天**「N 轮 · N 分钟」（`focusSummary.total`，宿主按 `FOCUS_STATS_DAYS`(7) 现算 —— **不是终身累计**，标签必须写「近 7 天」；窗口真源在 `constants.js`，widget / settings 一律 require，设置页副本 `STAT_DAYS` 由 check-shared 钉住）。`focusSummary` 缺失时（首推前）空态两行：`menuHint('还没有专注记录')` + `menuHintAct('跑一段计时就自动记上')`（灰底一句说明 + 蓝色一句怎么做，见下方「行版式单一来源」）；统计全 0 仍走正常三行（「今日 0 轮 · 0 分钟」），不换成空态。三行的标签一律走 `menuLabel()`，**不再自起 `.dshwv-focus-label`**（早先专注组的标签是 11px / `#6b7aa8` / `min-width:32px`，与计时、待办组的 `.dshwv-menu-label` 差一档，同一面板里各组长一样）。**`focusOn` 关着时 `focusStatsEl` 直接 `display:none` 且不渲染**：组里只剩本轮执行行，**不出现空统计**。**底部只有一个入口**「专注与计时设置」→ `openSettings('focus')`：原「计时设置」按钮在构造后运行期改名（`title` = 在设置页配置计时默认值与专注记录），专注不再单独占一行「专注设置」；`openSettings('timer')` 深链仍保留，两者都落设置页的合并卡（见 `10-settings-cards.md`）。**折叠摘要也合并到这一组**：计时状态后接「 · 今日 N 轮」（`focusOn && focusSummary` 时才拼，见上面的摘要一节），关着时只有计时状态。
  - **模型**（`models`，默认收起）：切模型最高频，排在计时组之后（待办 / 专注与计时两组都关掉时它就是第一组）；只有内置 DeepSeek 时整组 `display:none`，行内容见「多厂商模型菜单」。底部一行是「刷新全部 + 管理模型」两只按钮，**不再挂「余额」标签**：额度型模型也在这张表里，写成「余额 刷新全部」既重复又容易被读成「只刷余额」。「管理模型」→ 关菜单 + `openSettings('models')`（加 / 删模型、改密钥与字段路径只能在设置页做）。
  - **外观与音效**（`look`，默认收起）：大小 / 音效 / 音量 / **透明度** / 气泡 / **气泡内容**（跳设置页的「气泡设置」）/ 报时 / 锁定。**「气泡设置」独立成行**：它是个跳转按钮，与开关同排时长得像第二个开关，点错率不低。
  - **余额与用量**（`usage`，默认收起）：用量 / 峰谷 / **峰谷提醒** / 刷新余额 + 复制余额（文案随主显示变，见上面的余额条）+ **用量明细**（`openSettings('usage')` → 设置页「用量与账本」卡）。**其余数据组都有回设置页的入口**（气泡设置 / 专注与待办设置 / 管理模型），这一组不该缺：看完「今日 ¥x」想追「钱花哪了」时，不该逼用户自己想到「打开设置」再翻 Tab。主显示非 `deepseek` 时整组收起（余额条在组外常显，不受影响）。
- **专注组的执行区（同一组，键 `focus`）**：**只放「这一轮」的操作** —— **计时**（模式下拉 + 开始/暂停/继续）/ **放弃确认**（内联，仅需丢弃 ≥1 分钟的非休息轮时出现）/ **快捷时长**（设置页 `timerPresets` 的四档，一键开始；仅「倒计时 / 关闭」模式显示，当前时长对应档高亮；点击读自身 `data-min`，设置页改档位后不会按旧值开始）/ **当前行**（计时中：任务名 + 读数 + 暂停 + 重置；空闲有专注项：当前 + 任务名 + 开始；到点态隐藏）/ **目标**（倒计时时/分/秒三段或定时刻，按模式二选一）/ **双击提示** / **专注与待办设置**（`openSettings('focus')` → 设置页合并卡「专注与待办」；`openSettings('timer')` 深链同样落这张卡）。**这一组的全部配置只在设置页改**：默认时长、快捷档位、到点通知、提醒停留、只显计时、气泡常驻、留言与休息档、番茄循环都收在合并卡的「计时设置」区，菜单不再重复摆开关 —— 早先「到点通知 / 提醒停留 / 只显计时 / 气泡常驻」四行在菜单与设置页各一份，两套回填最容易出现「这边关了那边还开着」。页面保留本地副本（到点通知、提醒停留与「休息 N 分钟」按钮要用），由 `applyConfig` 回推。**语义：设置页写默认值，菜单写这一轮** —— 菜单里的 H/M/S 是「本轮目标」草稿；`saveCfg` 改为显式补丁（只提交本次改动键，宿主 `patchConfig` 对 `undefined` 键不生效），改目标 / 点快捷档 / 待办开始 / 再来一轮都不再写 `timerSec`，只有显式切换模式（写 `timerMode`）与改定时刻（写 `timerAt`，设置页没有该字段）会落盘。`applyConfig` 只在宿主默认值真的变化时回填三段输入（`cfgTimerSecSeen` / `cfgTimerAtSeen` / `cfgTimerModeSeen` 三个「见到过的值」），计时中收到的新默认时长先压进 `pendingTimerSec`，回到空闲由 `syncTimerMenu` 落地 —— 否则随手调一下音量（也会广播配置）就会把刚改好的目标打回默认值。**放弃确认**（`rowTimerConfirm` / `requestTimerDiscard`）：重置、切模式、换一条待办开始、点快捷时长都会清零当前进度，`timerProgressMs() ≥ 60000` 且非休息轮时先显示「已专注 mm:ss，放弃后本轮不计入记录」+「放弃本轮 / 继续计时」；低于 1 分钟或休息轮直接执行，不打扰。**刻意用菜单内联确认而不是系统对话框**：悬浮窗是独立置顶窗，对话框会抢焦点、把菜单顶掉。确认框紧随当前行，首次出现时 `scrollIntoView({block:'nearest'})` 滚到可见（修掉旧版在待办组点开始、确认行藏在另一组里看不见的问题）；每秒跟着进度刷新，关菜单即取消。**「只显计时」开着时**另有一行 `.dshwv-menu-hint` 提示「计时中双击小鲸鱼，可临时看一眼余额」（`rowTimerPeekHint` / `syncTimerPeekHint`），**只在「只显计时」开着且计时中 / 暂停时出现**：这正是用户「点了鲸鱼只看到时间」的那一刻，其余时候双击没有特殊行为，常显反而误导；`syncTimerMenu()` 与「只显计时」开关变更时各刷一次。
- **专注联动**（`focusOn` / `todoOn` 各管各的；`focusOn` 只决定记录与统计）：① 计时气泡尾注由 `withFocusTail` 追加「 · 专注：<任务名>」（任务名截 8 字），**不再受 `focusOn` 门控**；**休息轮（`timerIsBreak`）不挂尾注**——这一轮不在专注，挂着会让人以为休息也算专注；② 到点动作条第 3 个按钮 `timerTodoBtn`「完成这条」仅在 `!timerIsBreak && todoFocusText()`（当前有专注项）时出现，点击后进入**接力气泡**（见 `08-floating-remind.md`），顺序为 休息 N 分钟 / 再来一轮（休息轮为「继续专注」）/ 完成这条 / 知道了，其中「休息」与「完成这条」在休息轮都隐藏；③ **计时上报**在 `reportFocusSession()`：`focusOn` 开着就报，正计时 / 倒计时 / 定时三种模式跑完或中途放弃都报一条 `{mode,startAt,endAt,minutes,isBreak,abandoned}` —— **页面只说事实，什么算一轮归宿主判**（早先只在倒计时到点这一个入口记账，用户坐了 40 分钟正计时统计里却是 0）。门控四条：一轮只报一次（持久化的 `reported` 位，到点后重置 / 重载补弹「时间到」都幂等）；放弃且不足 1 分钟不报（本来就没进入状态）；**被打断的休息不报**（躺两分钟就被顶掉说明不了任何事，只往日志倒噪音），走完的休息报一条并带 `isBreak`（明细里留标记，天表不聚合它）；结束时刻取本轮真正的终点（走完用预定终点，跨零点的轮次因此归结束那天；放弃就是按下按钮那一刻）。**不搭通知的顺风车**：通知被静音时统计照记；④ **只有一个「专注记录」开关**：早先拆成「专注记录 + 计时结束自动记录」两个，前者描述里就写着「计时结束后自动记一轮」，关掉后者后整条链路变成什么都不记，用户只会以为开了功能却坏了

- **鼠标穿透**（`passThroughOn` / `passHoverActive`）：未接管时恒穿透，指针在鲸鱼或菜单按钮停留 `PASS_DWELL_MS`(1200ms) → `passTakeOver()`（`setIgnoreMouseEvents(false)` + 菜单按钮转实心常显）；接管后按常规命中测试，离开 UI 满 `PASS_RELEASE_MS`(700ms) → `passRelease()` 交回穿透（拖拽 / 菜单打开期间不交回）。穿透中且未接管时菜单按钮带 `dshwv-menu-btn-pass`（半透明 + 虚线环常显），切换穿透弹一次三行说明气泡（走 `showRemindBubble`，文案取设置页「文案」卡片（提醒文案分组）的 `passOn`/`passOff` 模板，红/绿沿用状态色，计时中跳过）。菜单里另有「穿透中 · 关闭穿透」逃生行（见上面的余额条一节）：完整约束见第三节第 17 条。
