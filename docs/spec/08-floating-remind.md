## 八、悬浮窗页面（续）· 提醒 / 计时 / 专注 / 深浅色

- **峰谷倒计时**（`peakCountdownText`）：第三行「今日已用 ¥x」后追加「· 距峰时 1h20m / 距谷时 45m」。时刻取宿主下发的 `state.peakNextAt`（第五节），页面只做 `at − now` 换算，**不实现第二套时段规则**（拿不到 `constants`）；缺失或已过点（`left <= 0`）不显示，不足 1 小时按分钟。
- **提醒气泡统一入口**（`showRemindBubble(lines)`）：峰谷切换 / 今日预算 / 低余额 / 穿透说明四类共用：清自动收起与 gif 淡出计时器 → 置 `bubbleRemindActive` + 行数组 → `restoreBubbleLines()` + `applyBubbleLines()` → 展开 → `setRemindAutoHide()` 按 `remindSec` 秒收起（`0` = 常驻）。计时中（`timerActive()`）或气泡关闭时 return，不打断计时（宿主系统通知兜底）。行数组由 `alertLines(key, vars, midColor)` 按设置页模板映射成三行，四处各传占位符与状态色。
- **今日预算提醒**（`budgetOn && budgetAmount > 0` 且 `todayUsage > budgetAmount`）：① `handleBalance` 首次越线（`overAmt !== null && !state.budgetOver && !firstBalance`，刚进入那次不弹）→ `showBudgetRemind(overAmt)` 弹三行（模板 `budget`，占位符 `{used}` `{budget}` `{over}`），停留 `remindSec`；② `render()` 默认分支第三行常驻「今日已用 ¥x · 超预算 ¥y」；③ 系统通知由宿主 `maybeNotifyBudget` 每天最多一次（第五节）。`applyConfig` 预算字段变更即重算 `state.budgetOver` 并 `render()`（非气泡中）。
- **低余额预警**（`lowAlertOn && lowAlertAmount > 0` 且 `balance < lowAlertAmount`）：① `applyLowAlert()` 把余额与「今日已用」加 `.dshwv-low` 变红（`lowBalanceHit()` 是唯一判据）；② `handleBalance` 首次跌破（`lowHit && !state.lowOver && !firstBalance`，刚进入不补弹）→ `showLowRemind()` 弹三行（模板 `low`，占位符 `{balance}` `{threshold}`）；③ 宿主 `maybeNotifyLow` 每天最多一次。与预算同时命中**以低余额为准**（更紧急，判定在预算后）。`applyConfig` 套用阈值后立刻 `state.lowOver = lowBalanceHit()` + `applyLowAlert()`，避免旧状态被当首次越线再弹。
- `sendIgnoreMouse(ignore)`：穿透开关唯一出口，按 `lastIgnoreSent` 去重；`scheduleHover(e)` 用 rAF 合并 pointermove 命中测试（`hoverAt(e)` / `hoverNow()` 供拖拽收尾与配置重算）。**菜单开着（`menuOpen`）时 `updateHover` 强制 `sendIgnoreMouse(false)`**：`overUI` 靠 `elementFromPoint`，指针掠过菜单边缘或透明间隙会误判「非 UI」把整窗切穿透，输入框点不进去。
- **菜单输入焦点**：窗口以 `focusable:false` 创建（`preload/lib/widget.js`，不抢主窗焦点），而 Electron 不可聚焦窗口**不派发键盘事件**：点得进输入框却打不出字，`win.focus()` 无效；`focusable` 是创建期选项、切换需销毁重建，故走运行时开关：`toggleMenu()` 时 `whaleApi.setInputFocus(true)` → 宿主 `win.setFocusable(true)` + `win.focus()`；`closeMenu()` 时 `win.blur()` + `setFocusable(false)` + `utools.showMainWindow()`（不还焦点设置窗会失焦隐藏）。`setFocusable` 不可用时静默降级。
- **菜单打开瞬间的穿透兜底**：`updateHover` 只在 `pointermove` 下发穿透，而「临时接管」的 `sendIgnoreMouse(false)` 依赖指针停在鲸鱼 / 按钮上。`toggleMenu()` 打开时必须再调 `passReleaseCancel(); sendIgnoreMouse(false)`：否则 `PASS_RELEASE_MS` 的恢复定时器可能在菜单展开后才开火，把整窗切成穿透，菜单画着却点不到输入框。
- **计时 / 定时 / 倒计时**（`timerMode` = `off|up|down|at`）：
  - 正计时从 0 累加；倒计时取「时 / 分 / 秒」三段输入（各自 0–23 / 0–59 / 0–59，互不钳制，可填 90 分）合计成秒（`TIMER_MAX_SEC = 86399` 上限）换算终点，三段全填 0 按 `TIMER_MIN_DEFAULT = 25` 分钟兜底；定时取 `HH:MM`（默认 `07:30`），今天已过则顺延到明天。
  - **菜单输入一律「回车才生效」**（`commitOnEnter(el, commit)`）：绑 `keydown` 的 `Enter`（`preventDefault` 后提交并 `blur()` 回显）与 `blur`（点到别处不丢编辑），替代 `change`：`change` 随输入 / 失焦触发，数字框打到一半会被钳制回填、光标跳。checkbox / select / 滑块（`.dshwv-range`）仍走 `input`/`change`（点击 / 拖拽，不涉及打字）。
  - **配套：`applyConfig` 不得回填正在编辑的输入框**。宿主每次广播配置都走 `applyConfig`，计时段原本无条件 `timerHour.value = ...`，打字途中会被覆盖；故用 `editing(el)`（`document.activeElement === el`）判断，**持焦点的输入框跳过回显**，否则 `commitOnEnter` 被静默架空。
  - **菜单里的计时读数与目标锁定**（`updateTimerStatus()` / `lockTimerTargets()`）：读数行（`rowTimerStatus`）只在计时中 / 暂停时出现，标签按状态写「剩余」（倒计时 / 定时）、「已用」（正计时）、「休息」（`timerIsBreak`），暂停时追加「·暂停」，数值走 `fmtClock(timerRemainMs())`。**只在菜单开着时按秒刷新**（`timerStep()` 内 `if (menuOpen)`，菜单关着不写 DOM），打开菜单时在 `toggleMenu()` 里补一次 —— 且必须在 `positionMenu()` 之前，否则按旧高度量取、菜单贴边时少算一行。气泡被点掉或自动收起后，用户仍能从菜单看到这一轮进度。计时中 / 暂停时**「目标」输入框置 `disabled`**：`timerArg` 在 `startTimer()` 就已固定，改了不影响本轮，不锁会让人以为「改完就能延长」而白等一轮；原 `title` 存进 `data-title0`，解锁时还原，锁定时提示「先点「重置」再改」。**「重置」按钮统一挂在读数行**（`resetTimer()`，清进度、模式保留），三种模式共用，正计时也有清零入口。
  - 倒计时 / 定时用「终点时间戳」（`timerEndAt`），1s `setInterval` 只刷新显示与判断到点，后台节流也不走时不准。倒计时气泡按 `HH:MM:SS`，`timerArg` 存**秒数字符串**作唯一事实源（「共 x」与「再来一轮」都按它复原）。
  - 计时气泡**常驻不自动收起**（`showTimerBubble(0)`），点气泡收起、计时继续；再点鲸鱼重新显示（`showBubble()` 在 `timerActive()` 时转 `showTimerBubble`）。
  - **到点后要做什么**（`timerNote` / `timerBreakMin`，**只在设置页「提醒与通知」改**）：`timerNote` 到点留言（单行，`TIMER_NOTE_MAX = 60` 字）；`timerBreakMin`「休息」按钮分钟档（0–120，0 = 不显示）。到点气泡显示留言（有留言走大字 `B` + 红色，无留言回「时间到！」`P` 样式），系统通知正文由 `timerDoneText()` 拼成「小鲸鱼提醒：<模式>结束（<时长>） · <留言>」—— 模式名走 `timerModeLabel()`，倒计时 `timerArg` 是秒数串，必须经 `fmtClock` 换算（早先直接拼出来是「倒计时结束（1500）」）；**休息轮的模式名是「休息」**，正文为「休息结束（05:00）」。
  - 到点动作条：独立 `div.dshwv-timer-actions` 挂 `document.body`（**刻意不复用 `.dshwv-menu`**，不跟随挂件透明度），`positionTimerActions()` 按气泡 `getBoundingClientRect()` 定位到气泡下缘、横向居中并夹在窗口内，空间不足翻到上方。四按钮：「休息 N 分钟」→ `repeatTimerTimer(timerBreakMin * 60, true)`、「再来一轮」→ `repeatTimerTimer(0)`（0 = 按上次 `timerArg` 复原）、「完成这条」→ 勾掉当前专注待办并关气泡（仅 `focusOn && !timerIsBreak && todoFocusText()` 时出现）、「知道了」→ `hideBubble()`。显隐由 `updateTimerActions()` 统一判定（`!timerFinished || !bubbleShown` 时收起），在 `showTimerBubble()` / `syncTimerMenu()` / `applyConfig`（专注或待办开关变化）/ resize 四处调用；`hideBubble()` 与 `timerPeekDone()` 直接移除 `dshwv-actions-open` 类（动作条与气泡同生共死）。**休息轮到点不给「休息」（刚休息完）也不给「完成这条」（这一轮没在专注），「再来一轮」改叫「继续专注」**：按休息前的专注时长接着计时，叫「再来一轮」会被当成再来一次休息。
  - 到点：`finishTimer()` 响提示音（`playPress()`，走音效开关与音量）→ 按 `timerNotifyOn || (timerMailOn && notifyMailOn)` 决定是否发 `whale:timer-done`（页面只管发不发，系统通知还是邮件由宿主按配置决定）→ `reportFocusRound()` 记一轮专注（`focusOn && !timerIsBreak && timerMode === 'down'` 才发）→ `restoreFocusAfterBreak()` 把 `timerArg` 还原成休息前的专注时长（必须在通知之后：通知要按「这一轮」的时长说话）→ 气泡显示「时间到！」与留言 → 按 `timerRemindSec` 秒后收起（菜单「到点通知」旁档位，默认 8s；0 = 常驻），`hideBubble` 里清结束态。
  - 持久化（`timerPersistOn`，默认开）：开始 / 停止 / 到点 / 切模式时上报落库（`whale:timer` 键，含 `isBreak` / `back`）；重建挂件时宿主在 `whale:init` 回推 `timer`，`restoreTimer()` 恢复 —— 正计时按 `startAt` 继续，倒计时 / 定时按 `endAt` 继续，挂件不在期间已到点则补一次到点流程（提示音 + 通知 + 气泡）。**休息轮必须一起恢复**：不存 `isBreak` 会把休息记成专注，「继续专注」还会按休息时长重启。关闭开关后不再落库，宿主同时删已有记录（`saveConfig` / `whale:config` 两条路径都 `clearTimer()`）。
  - 优先级：计时气泡 > 提醒类（峰谷 / 预算 / 低余额 / 穿透说明，共用 `showRemindBubble`）> 固定文案气泡（报时 / 动图降级，即 `bubble.system`）> 余额提示；计时中提醒类直接跳过。
- 刷新节奏：`whale:init` 后启动 60s 轮询；`visibilitychange` 隐藏（`win.hide` / 最小化 / 切虚拟桌面）时 `clearInterval` 暂停，重新可见先 `timerStep()`（补判到点）与 `refresh(false)` 拉一次再恢复轮询，避免后台空跑。
- **深浅色由 `uiMode` 合成**（`utools.isDarkColors()` + 配置偏好）：面板深浅形态挂 `<html>` 的 `dark` 类（`floating.css` 文末 `html.dark` 是唯一深色消费端）。生效值：`auto`（默认，取 uTools 实际深浅）/ `light` / `dark`（设置页「界面深浅色」，见 §十）。页面持两份状态：`uiMode` 偏好副本（`applyConfig` 回填，变更立即重合成）与 `utoolsDark` 缓存。实时值由 preload 轮询 `utools.isDarkColors()`（同步读，1s 间隔，无变更事件）：`floating.js` 轮询后 `emit('dark', …)` **本地推送**（preload→页面，不经主窗、非 `whale:` 通道，不进第五节通道表）；另暴露 `whale.isDark()` 同步读（首条推送早于页面注册回调，启动靠它补初值）。判定源**不是**配置 `theme`（气泡配色主题，两条线）。深色覆写只动颜色与 `color-scheme`；气泡四色（`--dshwv-text/hint/fill/stroke`）**不得**在 `html.dark` 覆写（check-shared 钉住，动了气泡会跟菜单换色）。**`saveCfg()` 必须原样带回 `uiMode`**（白名单铁律，同 `notifyMailOn`），漏带等于每次保存用 `undefined` 抹掉设置页选择。
