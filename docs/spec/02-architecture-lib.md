## 二、架构（续）· lib 模块职责（工具 / 诊断 / 素材 / 窗口）

  | 文件 | 职责 |
  |---|---|
  | `lib/util.js` | **通用工具**：`num`（脏值收敛 0）/ `isIpv4`（点分四段，`String()` 归一）/ `readBodyWithProgress`（流式读体 + 逐块报进度，`skin-packs`/`assets-packs` 共用）/ `dayKeyFromTs`（按本地时区归日，不按 UTC）/ `dayAdd`（跨月跨年）/ `homeDir`（env → `~/<fallback>` → 逐个 `existsSync` → 无则空串）/ `readTextSafe`（`ENOENT`/`ENOTDIR` 静默，其余回报 `reason`）/ `readText` / `readJsonSafe` / **`writeFileAtomicSync`** / `walkDir`（深度上限 + 名过滤）/ `normalizePath`。**依赖边界硬禁令：只允许 `path`/`os`/`fs`**：禁 `require('./log')`（其 `DEV` 依赖全局 `utools`）、禁 `require('utools')`、禁放跨文件同步常量（`check-shared.mjs` 不扫本文件）；违反症状 = 「构建通过但 `test/util.test.mjs` 在 require 阶段炸」，故该测试**不挂 utools 桩**，兼作边界自检。由 `dsh-usage`/`codex`/`diagnostics`/`store`/`hosts`/`skin-packs`/`assets-packs` 复用 |
  | ↳ **原子写 `writeFileAtomicSync`** | 「同目录临时文件 → `fsyncSync` → `renameSync`」，失败清临时文件、返回 `{ok:false,error}`（**不抛**）。**为什么**：`writeFileSync` 写一半被结束会留**截断文件**，对 `settings.yaml`/`package.json` 这类 dsh 直接解析的文件比「不存在」更糟；`renameSync` 同分区原子。已用于 `dsh-backup.js` 的 `meta.json`/`manifest.json`/`restoreSnapshot` 主写及其余 dsh 侧配置回写。**⚠️ 故障注入点必须落在 `atomicTmpPath` 上**：原子写把「写目标」换成「写临时 + rename」，替换 `fs.writeFileSync` 拦不到主写、只假绿；`util` 为此导出 `atomicTmpPath(file)` 作接缝；**主写必须按调用时从 `module.exports` 取它**（不能裸调局部绑定，也不能用 `exports.x`：文件末尾整体替换 `module.exports` 后模块内 `exports` 指向被丢弃的旧对象，运行时 undefined）。测试替换 `require('util').atomicTmpPath` 即改到下一次主写，`test/settings-allowbuilds.test.mjs` 据此注入 `ENOSPC` 验回滚 |
  | `lib/http.js` | **出网请求最小统一封装**：零依赖叶子（只 require `./util` 的 `errMsg`，零桩可加载）。`request(url, init, opts)` 只做三件事：**单次超时**（`AbortSignal.timeout`，`opts.timeout` 缺省 `DEFAULT_TIMEOUT_MS = 15000`）、**可选重试**（`opts.retries`，仅网络异常 + 5xx + 429，4xx 不重试；间隔 `opts.retryDelay` 缺省 `RETRY_DELAY_MS = 500`）、**结构化错误**。契约：2xx → `{ok:true, status, res}`（body 由调用方读）；非 2xx → `{ok:false, status, retriable, error:'HTTP <code>'}`（**不含 `res`**）；网络/超时 → `{ok:false, status:0, retriable:true, error:<errMsg>}`。**⚠️ 后两条路径无 `res`**：读 body 须 `r.res || {json:async()=>({}),text:async()=>''}` 兜底，判状态码一律用 `r.status` 而非 `r.res.status`。**刻意不做** in-flight 去重 / TTL 缓存 / 多源竞速 / 总预算均摊（语义正交：缓存归编排层、竞速归候选链、预算归业务）。统一 `api.js` 三处重复的重试循环（`fetchBalanceWith`/`fetchPlatformUsage`/`fetchModelJson`），仅被 `api` 引用 |
  | `lib/pnpm-compat.js` | **pnpm 失败归因分类器**：纯函数叶子（无 utools/fs/副作用，可零桩加载）。`classifyPnpmFailure(output, exitCode)` 归到 `pnpm-missing` / `profile-file-locked` / `windows-file-locked` / `transient-network` / `fetch-timeout` / `root-add` / `lockfile` / `release-age-violation` / `host-peer` / `unparseable-build-key`，认不出回落 `code:null`（**不猜**）；返回 `{code, retryable, reason, hint}`。`shouldAutoRetryOnce(info, opts)` 决定是否一次性自动重试。**只归因，绝不写文件、不自动改用户配置**（尤其不放行 release-age 白名单）。`RECOGNIZERS` **顺序敏感**，顺序即设计（见第五节 `retryable` 段）。被 `settings.js` 引用 |
  | `lib/offwork.js` | **下班倒计时纯计算**：零依赖叶子（可无桩单测）。导出 `DEFAULTS` / `NEAR_SOON_MS` / `NEAR_IMMINENT_MS` / `normHm` / `normDays` / `normPayday` / `normCfg` / `fmtDuration` / `display`。`display(nowMs, cfg)` 返回 `{phase, label, main, hint, near, remainMs, targetMs}`：`phase` 为 `before` / `work` / `after` / `off`，`main` 恒为倒计时（`after` / `off` 时倒到下一次上班），`near` 只在 `work` 且剩余 ≤30 / ≤10 分钟时给 `soon` / `imminent`。工作日按 JS `getDay()` 口径（0=周日）；`end <= start` 按跨日班（下班落次日），`carryShift` 处理「凌晨仍在昨天班上」，`nextStartAfter` 最多向后找 7 天。**只做本地 `Date` 构造、每个 tick 重算**（国内无 DST；系统时区变了下一轮自然跟上），**不做 IO、不读配置**。被 `store` 引用（配置归一）；构建期由 `vite.config.js` 用 esbuild 打成 `dist/offwork-core.js`（全局 `OffworkCore`），挂件页与宿主共用同一份源码 |
  | `lib/diagnostics.js` | **dsh 只读诊断**：C1 `duplicate-modules`（profile 的 `node_modules/@deepseek-ai/*` 与全局 dsh 树装出两份 → cordis 认成两个包 → `prompt section "deployment:persona" is already registered`、preset 挂不上）/ C2 `patch-entry-missing`（`cordis.patch.yml` 的 `- id: X` 不在组装树 → `patch: entry "X" not found` 起不来）/ C3 `patch-syntax`（行级扫描缩进跳变、`- id:` 缺值、`!!js` 引号未闭、重复 id）/ C4 `settings-yaml`（`$DSH_HOME/settings.yaml` 行级体检）/ C5 `port-3080`（3080 归属）。**三项硬约定**：① `detect` 绝不写文件；② 单项抛错只标该项 `threw` 并附 `err.message`，其余照常；③ `fixable` 本期恒 false。**C1 用身份指纹（`package.json` 的 `name` + `version`），不用 `realpath` 比对**：后者在 Windows（大小写不敏感 + junction + 8.3 短名）与 macOS（APFS 保留大小写）会**静默漏报**。**C5 尽力而为**：探测失败/归属不明报 `warning` + `reason`，**不影响其余四项、不让整轮 `ok:false`**。只读、不联网、不持凭据，结果缓存 `whale:dshDiagnose`（60s TTL，`force` 绕过） |
  | `lib/dsh-dump.js` | **dsh 配置转储**：一次 CLI 读取（`node <bin.js> --profile <n> --dump-config` 与 `--dump-default-config`，**串行**：并行会让 dsh 重复加载 profile），产出两块可视化：**D1 patch 分层**（分节头 `# == <包名>[, patched by <来源>]` → `patchedBy` 空归「基线」、绝对路径归「用户层」、包名归「包内层」；`layer-list` 层数等于实际来源数，不硬套五层模型）与 **D2 生效树 vs 默认树 diff**（按条目 id 对齐，比「包名 + `disabled` + config 字段名」三项；同 id 后出现的分节覆盖先出现的：patch 按 id 整体替换而非深度合并）。**六条约定**：① 子进程 8s 超时（`DUMP_TIMEOUT_MS`）、4MB 截断；② 输出必须过 `decodeOut()`（Windows 下 node 输出是 GBK，`toString('utf8')` 乱码、分节头全匹配不上）；③ `!!js '...'` **原样保留、绝不求值**，一律标 `disabled: true`；④ **只解析到条目级**，config 只留 key 名不留值（可能含密钥）；⑤ 缓存 `whale:dshDump`（60s TTL，`force` 绕过）；⑥ **一律显式写 `--profile <n>`**（`bin.js` 只在首个 token 不以 `-` 开头且非 `plugin` 时补，隐式依赖参数顺序会踩坑）。默认树读取失败属**降级**：`diff: null` + `diffError`，分层仍可用。**层内条目按 id 去重**：同一 bundle 会以「基线分节」反复出现，不去重条目数虚高；重复层标 `repeat: true`、界面注明「分节有重复列举」，`preview`（前 40 条）供渲染、`title` 放全量。纯只读、不改配置、不联网、不持凭据，复用 `dsh.js` 的 `decodeOut`/`spawnCmd`/`activeDsh`/`resolveNode` |
  | `lib/dsh-notes.js` | **dsh 宿主「更新说明」区间聚合**：发布页 `ungh.cc/repos/deepseek-ai/deepseek-harness/releases` 的 notes 已按语义分节（✨ 新增/🐛 修复/⚠️ 调整/🎨 优化），故**不做关键词风险判定**。增量是**区间**：notes 面向所有人，用户要看「实装版 → 最新版」的**累积**变更。对外只一个 `getNotes({installed,target,list,notes})` → `{ok,empty,versions,sections,total,truncated,url}`，**失败一律 `ok:false` 不抛**。**四条取舍**：① 实装 == latest 时区间为空、不发请求；② 正文单次 4s 超时、失败即止、**不串行重试**；③ 分节标题**中英归并**（中文「调整」、英文 `Changes`，不归并会拆成两节；`normTitle` 去 emoji/括号/空白并小写后查 `ALIAS`，故英文键写连写形式）；④ 区间下界只到列表下界，残缺标 `truncated` 如实说明。**无桩可加载**：不 require `utools`，纯字符串计算（外链动作留在设置页），调用方拿 url 后交 `services.openExternal` |
  | `lib/skin-packs.js` | **按需下载内置形象**：候选链（用户自填前缀 → `ghfast.top` → 直连 → raw 兜底）取 `skins-pack.whaleassets`，**双重 sha256**（整包 + 逐项）校验后解析容器写入自定义画廊。流式读体走 `util.readBodyWithProgress`（分块读 `res.body.getReader()` 累加字节并报进度，无可读流退回 `arrayBuffer()`，兼容单测假响应）。依赖 `download-progress`/`skins`/`constants`/`log` |
  | `lib/assets-packs.js` | **按需下载共享素材**：共享角色与共享音效库两个大包，与 `skin-packs` 同款候选链 / 容器解析 / 双重校验；流式读体统一走 `util.readBodyWithProgress`（两处 `total` 都取 `Content-Length`，差异只在上限校验常量，留在调用点）。依赖 `download-progress`/`skins`/`sounds`/`constants`/`log` |
  | `lib/download-progress.js` | **素材包下载进度单例**：内置形象/共享角色/共享音效三条链路**共用一份进度态**。写入 API：`begin(pack,total)` / `phase(name,extra)` / `source(url,label)` / `progress(received,total)` / `end(ok,bytes)` / `clear()`；读侧只有 `snapshot()`，**必须零副作用**（只读内存；设置页 250ms 轮询，副作用会被放大成每秒四次）。**`snapshot()` 返回副本**——回引用会让渲染层读到「半更新」字段组合。换源时 `source()` 把 `received` 归零（换源须重计）。拿不到 `Content-Length`（加速代理回 `Transfer-Encoding: chunked`）时 `totalKnown:false`，读侧显示不确定进度条而非谎报百分比。`end()` **保留快照**，由读侧按时间窗口（`DL_DONE_KEEP_MS`）自行忽略。最底层叶子，只依赖 `constants` / `log` |
  | `lib/data-dir.js` | **用户素材目录统一推导**：`baseDir()` / `dataDir(sub)`，顺序 `utools.getPath('userData')` → `utools.getPluginLocalDataPath()`（uTools 8.0 新增，长期保留、不参与同步）→ `os.tmpdir()`（最后一级必 `logErr` 留痕，不再静默）。**素材刻意不迁到插件本地数据目录**：搬家等于让老用户已下载的几十 MB 素材凭空消失，换不来可见收益。被 `skins` / `sounds` / `bubbles` / `media` / `bg-video` 共用，替代原本五份会各自漂移的副本。只依赖 `log`，不做 IO |
  | `lib/widget.js` | 悬浮窗创建/销毁/几何/缩放/**任务栏显隐跟随**/推送 |
  | `lib/ipc.js` | 悬浮窗 ↔ 宿主 IPC 路由 |
  | `lib/settings.js` | 对外 `window.services` |
  | `lib/notify.js` | **通知统一出口**：`notify(text, cfg)` 按渠道开关发**系统通知**（`utools.showNotification`）与**邮件通知**；内置手写最小 SMTP 客户端（Node `net`/`tls`，EHLO → STARTTLS(可选) → AUTH LOGIN → MAIL/RCPT/DATA → QUIT，三重超时兜底）与 MIME 组包（头部 CRLF、中文走 RFC 2047、正文 base64 折行 76 字符，见第六节「通知方式」段）。另导出 `sendMail`/`mailSubject`/`mailConfig` 供设置页「发送测试邮件」复用。**叶子**，只依赖 `constants` / `log` / `store`，无循环 |

  依赖单向：`constants → log → pricing → store → api → widget → ipc → settings`；`holidays.js` 位于 `log` 与 `pricing` 间（依赖 `constants`/`log`，**刻意不引 `pricing`** 以免成环），仅被 `pricing` 引用。`offwork.js` 零依赖叶子，仅被 `store` 引用（配置归一），挂件页经构建产物 `dist/offwork-core.js` 消费（不走 `require`）。`dsh` / `backup` / `assets` / `sounds` / `skins` / `bubbles` / `codex` 为叶子（只依赖 constants/log/store，`assets` 另依赖同层 `skins`/`sounds`/`bubbles`），仅被 `ipc`/`settings`/`widget` 引用，无循环（`widget` 只取三者 `get*Data()` 供 `whale:init` 回推）。`hosts.js` 复用 `store.normIps` 与 `dsh.psExe`（`dsh.elevateTool()` 备用，非 Windows 由 `!WIN` 挡下），同属叶子层，仅被 `settings` 引用。`notify.js` 同为叶子，被 `api`/`ipc`/`services`/`settings` 引用（**`store` 不得反向引它**，否则成环）。`util.js` **最底层**，只依赖 `path`/`os`/`fs`；`http.js` 零依赖叶子，被 `api` 引用；`data-dir.js` 只依赖 `log`，被 `skins`/`sounds`/`bubbles`/`media`/`bg-video` 引用；`diagnostics.js` 依赖 `util`+`constants`+`log`+`dsh`（只取 `probePort`/`snapshot`，**不改 `dsh.js` 导出面**），仅被 `settings` 引用，**宿主直返，不新增 IPC 通道**。`dsh-dump.js` 依赖 `log`+`constants`+`dsh`+`util`，仅被 `settings` 引用，**把 `dsh.js` 导出面扩了四个通用工具**（`decodeOut`/`spawnCmd`/`activeDsh`/`lastPathLine`）：前三个通用（复制必漂移）；`lastPathLine` 纯函数，单独导出便于单测。同样**不新增 IPC 通道**。
