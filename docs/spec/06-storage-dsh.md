## 六、存储结构（续）· dsh / Codex / 任务栏 / 节假日

| 介质 | 键 | 内容 |
|---|---|---|
| `dbStorage` | `whale:dshVersions` | dsh 可用版本列表缓存 `{at,latest,list,times}`（`npm view` 的 `versions` / `dist-tags` / `time` 合成；重载插件后仍可选；清除「窗口位置与更新缓存」时一并删除）。**`times` = 版本 → 官方发布时间戳**（`{<版本号>:<ISO 字符串>}`，取自 npm `time`，剔除 `created` / `modified`）。**版本先后一律按 `times` 判定，不能按 semver** —— dsh 会给旧分支补发号更低的补丁（实测 `0.1.5-rc.3` 晚于 `0.1.6-alpha.2`），还有跳号；按 semver 会把「后发但号更小」判成更旧，更新提示判反、版本说明区间漏版。`times` 缺失时（老缓存 / 上游没给 `time`）退回 semver（`dsh.js` 的 `isNewer` / `dsh-market` 的 `cmpVer`），见 `lib/dsh.js#newerByTime` 与 `lib/dsh-notes.js#after` |
| `dbStorage` | `whale:dshNotes` | dsh release **说明正文持久缓存** `{version,at,items:{<版本号>:<markdown>}}`（`version` 目前为 1）。**只存上游正文，不存聚合结果**：聚合（`dsh.js` 的 `state.notes.data`）随区间变，落库会「版本号新、说明旧」；正文不可变，跨会话复用安全。**收益**：主源每次吐全量 release，区间通常只用 1~3 版，落库后第二次看同一区间**0 请求**（`dsh-notes.js#collect` 先查缓存，`want` 全命中就跳过网络）。最多留 `CACHE_MAX_VERSIONS` 40 版，超出按版本序淘汰最老。**纯派生数据、不含凭据、不进备份**；清除「窗口位置与更新缓存」时随 `whale:dshVersions` 一并删除。**来源**：`dsh-notes.js` 的 `SOURCES` 按序回退、**按速度排** —— ① `gh-proxy.com` 代理 github api（主源）② `api.github.com` 直连（备源；**单 IP 限流 60/h，不日常用**）③ `ungh.cc`（兜底）。拿到合法 JSON 即停，正常路径只打一次。两个 github 源带 `per_page=100`（默认只返回 10 条，会让区间里十几版静默变空正文）。整条链路共用 `TIMEOUT_MS` 10s 总预算、按剩余源数均摊。 |
| `dbStorage` | `whale:dshVersionsQueried` | dsh 版本「查过没有」的 `true` 标记（与 `whale:dshVersions` 分开存：列表可能为空，但「查过」决定展开「运行详情」时是否自动打一次 `npm view`、以及「查询可用版本」按钮是否还挂着）。**纯派生数据、不含凭据、不进备份**；清除「窗口位置与更新缓存」时一并删除 |
| `dbStorage` | `whale:dshAutoRefreshVersions` | 「进入开发者 Tab 自动刷新可用版本」勾选的 `true` 标记（设置页 dsh 主控卡的勾选项，**只在设置页侧读写**：勾上后每次切进开发者 Tab 由 `dshQueryVersions` 重打 `npm view`，勾选瞬间也补查一次。默认不勾：查询要联网，须用户显式授权；不勾时沿用 `whale:dshVersions` 的无 TTL 缓存。**纯偏好开关、不含凭据、不进备份**，与 `whale:dshVersionsQueried` 同批随「窗口位置与更新缓存」清除 |
| `dbStorage` | `whale:models` | 多厂商模型的**运行时状态** `{ [模型 id]: {at,date,balance,currency,todayUsage,prevBalance,usedPct,resetAt,windows,tokens,monthTokens,error,lowNotifiedOn,keyId} }`（`windows` = 多窗口额度的各窗口已用%；`tokens`/`monthTokens` = `kind='codex'` 的今日/本月 token；`keyId` = 该模型密钥指纹，换 Key 只重置记账基准、不把余额差记成用量，同内置 DeepSeek 的 `keyFingerprint` 口径，见 `api.js#keyChanged` 分支）。**只用于展示与预警、不参与记账，不进备份**（备份里 `config.models` 才是用户填的那份）；删模型时 `dropModelState(id)` 一并清掉 |
| `dbStorage` | `whale:codex` | Codex 本地会话统计的**增量解析缓存** `{version,files:{[绝对路径]:{size,mtimeMs,days,rl,rlTs,skipped?}}}`（`days` = `{YYYY-MM-DD:{模型:{in,cached,cwrite,out,reason,total,turns}}}`；`rl`/`rlTs` = 该文件最新订阅窗口快照及其时间戳；`skipped:true` = 超单文件上限、已跳过但**指纹已落缓存**）。按 size/mtime 判是否重解析。**`version` 目前是 2**：v1 条目没有 `rl/rlTs`，指纹没变就不会重解析，版本不符时当空缓存重扫一次。**两级上限**（`codex.js` 顶部常量）：① **单文件 `CODEX_MAX_FILE_BYTES` 32MB** —— 超限不解析但写指纹并标 `skipped`：解析同步占主线程，超大文件抛 `ERR_STRING_TOO_LONG` 且发生在写缓存之前；不写指纹则每轮都被判「变更」重读，**永久复发**。② **单轮预算 `CODEX_MAX_ROUND_FILES` 400 文件 / `CODEX_MAX_ROUND_BYTES` 96MB**：只解析预算内文件，其余不写指纹、留到下一轮（返回 `deferred:true`）；未解析的下轮仍在「变更」桶，故必须**先分桶（fresh/reused）再按预算解析**，否则边扫边判会让前几个文件吃光预算、进度永不前进。**纯派生数据、不含凭据、不进备份**，可由「清除缓存并重扫」删除重建 |
| `dbStorage` | `whale:dshDiagnose` | dsh **只读诊断**结果缓存 `{at,ok,pass,bad,results,env}`（`results` = 五项检查的完整结论，**明细不截断**：设置页只渲染前 5 行，超出由「复制诊断信息」给出全量）。60s TTL，`force:true` 绕过。**纯派生数据、不含任何凭据、不进备份**；也**不建议挂进 `clearAllData`**：留着无害，清掉只换来一次重扫。写入失败只 `logErr`，不影响本次诊断结果的返回 |
| `dbStorage` | `whale:dshUsage` | dsh 本地用量统计的**增量解析缓存** `{version,files:{[绝对路径]:{size,mtimeMs,agg}}}`（`agg` = 该会话缓存文件解析出的 `{at,day,model,provider,tokens,inTok,cached,outTok,reason,cost,turns}`）。只缓存 `storages/session_projcache/sessions/*.json`（按 size/mtime 判断是否重解析）；`dsh-usage/usage-ledger.json` 与 `provider-snapshots.json` 体积小，每次直接读。**纯派生数据、不含任何凭据、不进备份**，可随时由「清除缓存并重扫」删除重建 |
| `dbStorage` | `whale:dshDump` | dsh **配置转储**结果缓存 `{ok,at,profile,sections,layers,entries,unparsed,diff,diffError}`（`layers` = 分层聚合；`entries` = 生效树条目骨架，**只含 config 的字段名、绝不含值**；`diff` 三个数组各截断到 200 条，总数在 `*Total`）。60s TTL，`force:true` 绕过。判据是 `v.at && Array.isArray(v.layers)`（缺项的半截缓存当没有）。**只缓存成功结果**：失败结果写进去会让用户点「重新读取」也拿不到新结果。**纯派生数据、不含任何凭据、不进备份**，可随时由 `clearDshDumpCache()` 删除重建 |
| `dbStorage` | `whale:dshMarket` | dsh **插件市场目录的离线副本** `{at,updated,source,categories,plugins}`（`at` = 落盘时间戳；`updated` / `source` 取自目录本身）；60s 内存缓存之外的持久化副本，**抓取失败时降级读它**（`settings.marketCatalog` 回 `ok:true` + `from:'cache'` + `stale:true` + `staleReason`，让用户至少看得到上次的清单）。**纯派生数据、不含任何凭据、不进备份**，可随时重抓覆盖 |
| `dbStorage` | `whale:taskbar` | **任务栏方向/厚度探测结果的落盘兜底** `{edge,size}`（`lib/widget.js`）。`createBrowserWindow` 前必经 `usableArea()`，自动隐藏任务栏的机器会走 `taskbarFromRegistry()`（同步 `execFileSync('reg', ...)`，冷启动几十至上百毫秒）；内存 `tbCache` 随进程消失，于是每次冷启动都要同步起一次进程、拖慢首帧。落盘后模块加载即回填为初始缓存（回填时 `at` 置 0 = 仅启动期兜底，避免过期值被一路续命）。**纯派生数据、不含凭据、不进备份**，最长滞后一个 `TB_TTL`(60s) |
| `dbStorage` | `whale:cnHolidays` | **法定节假日表的联网更新覆盖层**（`lib/holidays.js`，用户手动点「更新节假日表」后才写入）：`{fetchedAt:number, dates:string[], years:string[], sources:{[年份]:源下标}, failed:number[]}`。`dates` 只存**放假日子**（`YYYY-MM-DD`），与内置表 `constants.CN_HOLIDAYS` 取**并集**参与峰谷判定（`pricing.isPeakTime` → `holidays.isHoliday`），**纯加法**、不删内置日子。**默认零网络**：只有设置页「挂件外观」卡点「更新节假日表」时才拉（当年 + 次年，多源回退）。「恢复内置表」即回纯内置表。**纯派生数据、不含凭据、不进备份**，可随时重取。供 `settings.holidayStatus/holidayUpdate/holidayClear` 读写 |
| 文件 | `<userData>/whale-hosts-backup` | **GitHub 加速首次开启时的原 hosts 副本**：由提权脚本在写入前复制，供误操作手动恢复；正常关闭走「删块」不需要它。**卸载 / 清除插件数据不影响系统 hosts**（系统文件，本插件只追加/删除自己的标记块），需还原请在「帮助 → GitHub 加速」先关闭再卸载 |
