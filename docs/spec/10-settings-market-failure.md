  - **⚠️ 失败原因要「结构化」回传，别只回一句中文**（2026-09-24 补强，对齐 dsh-market 的失败码体系）：原先失败体只有 `ok:false` + `error` 一句中文，界面只能整串显示。现补三个**机器可读**字段，界面据此分派，不靠正则匹配文案：
    - **`staleReason`（`'release-age'` | `'allowlist'` | `'unknown'`）**：解决「版本没动」两种成因分不清的问题。`minimumReleaseAge`（最小发布年龄 / 观察期）与 `minimumReleaseAgeExclude`（白名单）要用户做的事**相反** —— 前者只能**等它满期**（白名单配置对观察期无效），后者才要把目标版本加进白名单。并成一档会让「太新」的用户改错地方。判据是 `pnpm` 输出里的关键短语（`too new` / `newer than … days` / `minimum-release-age` vs `minimumReleaseAgeExclude` / `ERR_PNPM_*`），**必须先看「太新」**：pnpm 报太新时会顺带打出白名单键名，先判 keyHint 就永远归到 allowlist。`policyKey` 随 reason 走（release-age → `minimumReleaseAge`，其余 → `minimumReleaseAgeExclude`）。
    - **⚠️ `retryable` 改成由统一分类器判定（v1.10.x，`pnpm-compat.js`）**：早先 `retryable` 由各失败分支随手给布尔（`!build` 之类），语义漂移：同为「不能原样重试」却有的给 `true` 有的给 `false`，界面拿它决定「给不给重试按钮」就会时灵时不灵。现改为**单一事实来源**：`lib/pnpm-compat.js` 的 `classifyPnpmFailure(output, exitCode)` 把 pnpm 输出**归因**成失败码之一，`retryable` 是该分类结果里的一个字段，由识别器统一给。
      - **顺序敏感**：`RECOGNIZERS` 是一张有序表，**顺序即设计**（`pnpm-missing` → `pnpm-stalled` → `profile-file-locked` → `windows-file-locked` → 网络类，`release-age-violation` 必须先于任何宽泛的 `ERR_PNPM_*` 兜底）。`pnpm-stalled` 必须排在锁类与网络类**之前**：它的原文会把超时前打印过的全部输出一起带出来，里面常混 `EBUSY` / `ECONNRESET` 字样，排在后面就会被抢走，把「某个包的安装脚本卡死」误报成「文件被占用 / 网络抖动」，真正卡住的包始终没被点名。改动表里的顺序 = 改判据优先级，必须同步改回归测试。
      - **只归因、绝不自动改用户配置**：分类器是纯函数叶子（无 utools / 无 fs / 无副作用），只回答「这是什么错、能不能原样重试、建议用户做什么」，**不写文件**。尤其**绝不自动放行 release-age**（往 `minimumReleaseAgeExclude` 追加条目）—— 那是供应链安全边界。
      - **失败码**：`pnpm-missing`（`findPnpm` 找不到，仅 `exitCode === -1`）/ `pnpm-stalled`（安装脚本长时间无输出被 pnpm 看门狗杀掉，文案会倒查输出里**最后一条** `node_modules/<包名> install$` 点名罪魁，认不出就省略） / `profile-file-locked`（含内层锁 `[\\/]\.pnpm[\\/]lock\.yaml\.\d+` 形态；`retryable=false` —— 锁没释放时原样重试必然再撞）/ `windows-file-locked` / `transient-network` / `fetch-timeout` / `root-add`（workspace 根目录用 `--dir` 装但没带 `-w`）/ `lockfile-outdated`（`ERR_PNPM_OUTDATED_LOCKFILE`，清单改了 lockfile 没跟上）/ `lockfile-broken`（`ERR_PNPM_LOCKFILE_MISSING_DEPENDENCY` / `Broken lockfile`，结构本身坏了，文案给出「只删 importer 记录 + `--no-frozen-lockfile --lockfile-only` 重建、**不要删整个 pnpm-lock.yaml**」）/ `release-age-violation`（三道门：`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` / `ERR_PNPM_NO_MATURE_MATCHING_VERSION` / **`ERR_PNPM_RESOLUTION_POLICY_VIOLATIONS_UNHANDLED`** —— 后者是策略在 lockfile 校验后重新应用时的第三张脸（上游 ca7fd10），成因与出路完全相同，归到这里才能说「等它满期」而不是甩一句内部错误）/ `host-peer`（宿主包声明成 peer 而 registry 拉不到，**正则要吃 `%2f` 编码斜杠**，真实报错形如 `GET …/@deepseek-ai%2fdsh-settings`）/ `exact-version-missing`（`ERR_PNPM_NO_MATCHING_VERSION` **且**请求是精确 `pkg@x.y.z`：当前线路还没同步到刚发布的版本，**不等于版本不存在**；范围请求匹配不上不归这档，宿主包留给 `host-peer`）/ `unparseable-build-key`。认不出回落 `code:null` + `retryable:false`（**不猜**）。
      - `window.services.classifyPnpmFailure(text, exitCode?)` 是它的只读透传（走宿主 API 直接返回，**不新增 `whale:` IPC 通道**），设置页拿它把原生输出翻成人话。
    - **⚠️ 一次性自动重试的窄口径（v1.10.x，`shouldAutoRetryOnce`）**：分类器归因之后，宿主在 `installPluginPkg` / `uninstallPluginPkg` 失败时**最多自动重试一次**，且只在三种情形：① `transient-network` / `fetch-timeout` —— 原样同 argv 重跑；② `exact-version-missing` —— 镜像 packument 还没同步，同 argv 再拉一次有机会命中（上游 #927 / `install.ts` 同款；它的 `retryable` 仍为 false，因为手动重试没有新信息）；③ `root-add` **且** `<profile>/pnpm-workspace.yaml` 存在 —— 补一个 `-w` 重跑。**绝不重试** release-age（等时间才有用）、白名单（要改配置）、`install --no-frozen-lockfile`（会绕过 lock 完整性，属于「替用户做危险决定」）。返回体新增 `failureCode` / `autoRetried`，错误文案在真重试过后追加「（已自动重试一次）」，让用户知道这次失败是重试后的结论。
    - **⚠️ `-w` 不能无条件加**：`-w` 会把依赖装到 workspace **根**而非 `--dir` 指的 profile。只有 profile 下真有 `pnpm-workspace.yaml`（那才构成 workspace）时补 `-w` 才成立；没有该文件时补 `-w` 会让 pnpm 直接报错。故 `root-add` 的自动重试以 `hasPnpmWorkspace()` 为前置。
    - **`mismatch` + `expected`**（RESOLVED_VERSION_MISMATCH 语义）：`pnpm` 报成功、版本也变了，但**低于目录目标**（镜像源滞后）。⚠️ **高于目标不算 mismatch** —— 镜像异步同步，可能抢先发布比目录还新的版本，那是**好事**，报成失败会把用户引向无谓排查。与 `blocked`（没变）、`downgraded`（相对更新前变低）是三条**互不重叠**的判据，`marketUpdate` 里按 blocked → downgraded → mismatch 顺序判定，命中即 `ok:false`。
    - **`tail`**：原生命令输出的**尾部 40 行**（`tailLines` + `OUT_TAIL_LINES`）。pnpm 的关键诊断（错误码、`For example:` 段、哪个包违规）一律在**末尾**，前面全是 `Progress: resolved … reused …` 进度噪声。按**行**保留而非按字符切 —— 按字符可能把最后一行（往往就是错误码那行）切半。超限时前缀「（省略前面 N 行）」标明省略量，否则用户以为这就是全部。
    - 类型侧 `DshMarketInstallResult` 加 `staleReason` / `retryable` / `mismatch` / `expected` / `tail` / `failureCode` / `autoRetried`。前端 `dshMarketConfirm` 的失败分支据此分派：release-age 明说「等它满期后重试即可，**不必改配置**」，mismatch 点明「实装版本低于目标（期望 x，实装 y）」，`retryable` 为真时给「重试一次」按钮。
  - **⚠️ `retryable` 必须真的被消费，否则等于没判**（v1.10.x，补齐 `useDsh.ts` / `App.vue`）：早先 `retryable` 只回传到界面、除了文案没有任何动作消费它 —— 判了半天「原样重试有戏」，用户只能自己再点一遍完整流程（重新 dryRun、重新过单据）。现在失败卡在 `retryable === true && !hostIncompatible && !aborted` 时多两颗按钮：「重试一次」（`dshMarketRetryNow`，**重跑一遍 dryRun** 再真写 —— 不新增旁路，链路与首次完全相同，只省了重新点目录条目）与「知道了」（清掉提示）。显示条件里 `hostIncompatible` 是硬排除：宿主不兼容**不是**靠重试能解决的。
    - `settings-allowbuilds.test.mjs` 补回归：`mismatchResolved` 三向（低于 / 等于 / **高于目标不报错**）+ 不可解析不猜、`staleReason` 双档（太新劝等满期 vs 白名单给可照抄行）+ **判据优先级**（两个线索同时在时以「太新」为准）、`tailLines`（截尾标省略量 / 不超限原样返 / 空输入不拼脏文案）、pnpm 失败时 `tail` 带出真因且 `retryable:true`。
