- **「dsh 插件市场」卡片调用链（「开发者」Tab）**：经 `window.services` 走九个 API —— `dshMarketCatalog(opts)`（**Promise**，`{force,url,mirror,registry,official}`；返回 `DshMarketCatalogResult`，含 `from`（胜出来源）/`tookMs`（竞速耗时）/`registry`（胜出镜像地址，官方源为空串），失败降级带 `from:'cache'`/`stale`/`staleReason`）、`dshMarketStatus(opts)`（**同步**，返回 `DshMarketStatusResult`，读 `profile/package.json` 的 `dependencies` 与用户层 patch 条目，合成 `installedMap`）、`dshMarketInstall(opts)` / `dshMarketUninstall(opts)` / `dshMarketUpdate(opts)`（**Promise**，`dryRun` 预览 / `dryRun:false` 落笔，落笔前强制快照 + 回读核验；`dshMarketUpdate` 与 install 同链路，reason 为 `before-market-update`）、`dshMarketCheckUpdates(opts)`（**同步**，`{profile, catalog}` —— `catalog` 由界面原样传回，宿主不联网；回 `DshMarketCheckUpdatesResult`，含 `entries` / `updates` / `unknown`，每条 entry 为 `DshMarketUpdateEntry`：`state` / `installed`（**实装版本**，读不到为空串）/ `range`（**声明范围**，如 `^0.5.11`）/ `latest` / `basis`（`'realized'` | `'range'` | `'none'`，界面据此选文案））、`dshMarketRegistries()`（**同步**，回内置 registry 列表）、`dshMarketPing(opts)`（**Promise**，并发打各源元数据、按延迟升序回列表，**只测速不改配置**）、`dshMarketRegistryLatest(opts)`（**Promise**，`{items:[{pkg,key}], registry?}` —— **回源 registry 查每包官方最新版**，纯手动触发，见下条）。**同步 / 异步混用是这张卡最易踩的坑**：`dshMarketStatus` / `dshMarketCheckUpdates` / `dshMarketRegistries` 直调返回，其余六个必须 `Promise.resolve(...).then(...)`。四个配置项（`dshMarketUrl` / `dshMarketMirror` / `dshMarketRegistry` / `dshMarketOfficial`）落 `whale:config`，与 `defaultConfig` / `readConfig` / `writeConfig` / `patchConfig` 四处同步；目录离线副本落 `whale:dshMarket`（见 §6）。
  - **⚠️ A 层宿主兼容性拦截：确证不兼容就拦在写入前，但给一条「强制安装」的出路**（`dsh-host-compat.js` + `settings.js` 的 `enforceHostCompat` / `hostBlockedResult`）：插件 manifest 可声明所要求的 dsh 版本（`engines.dsh` / `dsh.engines.dsh` / `peerDependencies['@deepseek-ai/dsh*']`），装前先判「当前宿主满不满足」。**⚠️ 只要包声明了 `engines.dsh`，就只按它裁决、peer 一律忽略**（宿主 dsh-app-boot 的 `unmetRequirements` 就是这么判的，上游 a4febfa 对齐）：两者是「优先替代表」而非合取，合取会把「engine 满足、peer 不满足」的插件误判 `incompatible`，而宿主本可加载 —— 用户装得上的插件被标红，比漏报更糟。只有没写 engine 时才看 `peerDependencies`（多条之间仍是合取，一票否决）。三态 `compatible` / `incompatible` / `unknown`，**只拦确证的 `incompatible`**：`unknown`（没声明 / 拉不到 manifest / 联网失败）一律放行 —— 目录里近一半条目没有 DSH 声明，拦掉等于废掉插件市场，「没查到」也不等于「不兼容」。
    - **判定要用零依赖手写 semver**（`dsh-market.js` 的 `parseVer` / `cmpPre` / `cmpVer` / `rangeAllows` / `lowerBoundOf`）：项目强制不装包。`^0.1.7-rc.1` 等价 `>=0.1.7-rc.1 <0.2.0`，而 `0.1.7-alpha.2` **低于** `0.1.7-rc.1`（预发布标识符按 ASCII 比，`alpha` < `rc`）—— 故判 `incompatible`。**这里按 semver 是刻意的、与「更新版本」那条相反**：本条判「插件声明的 dsh 版本范围（engine 优先，否则 peers）是否涵盖宿主版本」，范围语义由 semver 定义，只能用 semver；而「dsh 有没有新版」必须按发布时间（见第六节 `whale:dshVersions` 的 `times`）。两种比较各有语义，不要混用。
    - **宿主版本取 `diagnostics.readEnv().dshVersion`**（内部走 `snapshot()` 的 `resolved || installed || globalVersion` 三级回退），不自己另读一份 —— 否则会出现「诊断卡说一个版本、兼容性按另一个版本判」的矛盾。
    - **真因是「装上也无法加载」，不是安全问题**：dsh 加载插件时按同一份声明校验，版本不满足会拒载。拦的是白等一次 pnpm + 装出加载不了的包。
    - **⚠️ 拦截返回体刻意复用「前置失败」的形状**（`hostBlockedResult`）：`ok:false` + `retryable:false` + `hostIncompatible:true` + 明确 error 文案，**不带 `changed:true`** —— 界面本就靠「changed 才给确认按钮」自动挡住，不必再认专门字段。`retryable:false` 是因为原样重试必然再失败，唯一出路是换版本 / 换插件 / 升 DSH。
    - **⚠️ 拦是要拦的，但不能拦死**：界面上给一颗「仍要强制安装」按钮（`dshMarketForcePlan`），点它把 `force: true` 传给宿主。`force` 的语义**只把 `blocked` 压成 `false`，结论不变** —— 判定照做、`hostIncompatible` / `hostForced` 照样回传，界面据此在单据卡画警示条（`.mkt-plan-warn`，琥珀色，刻意不复用 `.err` 红）、结果卡补一句「若 dsh 加载失败先回滚快照」。`.mkt-plan-msg` 的 `message` 尾部追加「⚠️ 已忽略宿主兼容性检查（强制安装）：该插件要求 DSH …，当前宿主是 … —— 装上很可能无法加载。」
    - **⚠️ 真写必须自己再过一遍兼容闸**（`marketInstall` / `marketUpdate` 的 `force` 都要带**两次**）：dryRun 与真写是宿主上**两次独立调用**（界面先 dryRun 拿单据、用户点头后再调真写），两道闸判同一件事。dryRun 放行不代表真写放行；更要紧的是反向情形 —— 用户点了「仍要强制安装」、界面把 `force` 带回来，若真写不读 `force`，他看完成功单据点确认却照样被拦在写入前，**比不给这个按钮更糟**。
    - **✅ 教训（真实 bug）**：`enforceHostCompat(entry, opts)` 早先是**两个形参**，加 `force` 时并进 `opts`，但 4 个调用点都只传**一个**对象（把 `spec`/`npm`/`version`/`force` 一起塞在第一个参数里）→ `o` 长期恒为 `{}`，`force` 永远读不到，症状正是「点了强制安装、看了警告、按了确认，依旧被拦在写入前」。修法是统一从 `entry` 取值（`opts` 仅在显式传对象时补充）。**新加开关类参数时必须核对每个调用点的实参个数**。
