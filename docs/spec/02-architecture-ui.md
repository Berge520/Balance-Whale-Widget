  - **`AccelView` 的实时进度**：开启最慢，进度经顶部 `.gh-live`（呼吸圆点 + `ghAccelLiveText`）常驻显示「正在筛选可用 IP（已测 n/m 个）」：取 `ghAccelRunning` 里最后一条 running 步骤的 `detail`，由宿主 `opProgress` 持续改写。
  - **`nowTick` 心跳（60s）**：「上次刷新 N 分钟前」与「超 7 天未刷新」纯 computed 不会自己走字。仅在帮助 Tab 激活时用 60s `setInterval` 驱动 `nowTick`，卸载与切 Tab 时清理。
  - **日志轮询**：仅在有 running 操作时以 500ms 轮询 `ghAccelOpLogs()`（宿主每次深拷贝日志），无操作时零开销；`document.hidden` 时跳过本轮，回前台由 `visibilitychange` 立即补一次。
  - **`AccelView` 的来源可配置化**：候选链不再是写死的「DoH > 源表 > 当前表 > 内部兜底」，而由 `ghAccelSrc` 三个开关（未勾的来源整段不参与）与 `order` 决定；`community=false` 时 `hosts.enable` 连社区源表都不拉，`doh=false` 时不发起实时解析（步骤日志记 `skip`），`manual=false` 时跳过当前 IP 表。**三者全关时直接拒绝开启**（前端当场拦下并弹回勾选，宿主 `hosts.enable` 还有第二道同判据拒绝，不弹 UAC、不留坏块）。刷新与开启**共用同一套候选链**（`refreshIps` 改为逐段推进、凑齐即停），且**短路判据是「真的探通」而非「源给了 IP」**（某源给一堆不可达 IP 时按「已覆盖」收工，剩余域名再无来源可用）；但 `community` 段内部仍全部拉取（源 A 只覆盖少数域名时不能停手，否则 B 的域名全丢，且源表顺序是「同域名取排最前的源」的判据）。
  - **候选排序与来源编码**：`probeIp` 返回 `{ok, ms}`，`filterReachable` 收集可达候选时挂上实测耗时，最终 `arr.sort((a,b) => (a.rank-b.rank) || (a.ms-b.ms) || (a.idx-b.idx))`：**同域名多候选按「来源优先级 → 实测延迟 → 链内位置」排序**（hosts 是 first-match，慢的写前面＝每次白等；延迟排在来源优先级**之后**是刻意的，用户把某来源提到第一位就该让它优先）；来源标记编码为 `key\u0000真实来源`，建候选时拆出 `rank` 供排序，界面仍只显示「社区源表 · xxx」这类文字。`probeIp` 并发受 `PROBE_CONCURRENCY = 6` 限制（`Promise.all` 会瞬间推光全部请求、卡住渲染线程）；跨段复用同一 `(域名, IP)` 的探测结果不重复探。补测轮（`enable` 首轮 github.com 未达标后用社区源新 IP 再探）传 `srcKey:'community' + skipSrc:true`，让补测候选**整体前移到该来源应有的位置**（否则源表 IP 静默排到 DoH 之后，「源表优先」失效），且不重复打两行步骤日志。
  - **`refreshIps` 旧值复验**：探测不通的域名**不直接沿用旧值**，而是把当前表旧值也过同一套 `probeIp` 复验：旧值可能早已失效，直接写回会在 hosts 留一条解析不通的映射，比不写更糟（不写还能回落到 DNS 真实解析）；复验通过才沿用（来源追踪标「当前 IP 表（手填，旧值复验可用）」），复验也不通就**不写这个域名**（来源追踪注明，`dropped` 计数进摘要）。
  - **操作日志标题动态生成**：`settings.ghAccelRefreshIps` 用 `hosts.srcChainLabel(src.order, src)` 生成标题，而不是写死：标题由 preload 侧 `runGhAccelOp` 开篇生成，用户没打开设置页时也要正确，故由宿主按同一份 `normSrcOrder` + 开关算、只列实际参与的来源（写死则关掉 DoH 或调换顺序后标题照旧，`test/hosts.test.mjs` 已钉住）。
  - **`saveConfig` 反向回推**：`saveConfig` 末尾 `emitConfigChange()` —— 宿主 `patchConfig` 会归一化（如 `ghAccelSrc` 补全 / 去重），不回推则设置页手里还是自己拼的未归一化值，表现为「点『上移』没反应」。
  - **`writeConfig` 写失败留痕**：`store.writeConfig` 把 `utools.dbStorage.setItem` 包进 `try/catch`，失败 `logErr('[whale][config] 写配置失败', err.message)` 并返回 `false`（成功 `true`）。dbStorage 写满 / 配额超限时 `setItem` 会抛，裸抛到 IPC 层会让设置页停在「保存中」；与账本侧（`writeLedger` 等）统一为「失败留痕 + 返回值可判」。`patchConfig` 不透传该返回值（配置项幂等，失败后下次改任意一项会整体重写）。
  - **CSS 变量挂 `:root` 全局真源**：主题令牌已收敛到 `main.css` 的 `:root` 与 `html.dark` 一套（深浅判定跟 uTools，见 §十，不再用深色媒体查询），沿 DOM 继承覆盖全页：scoped 只给**选择器**加 `[data-v-x]`，不影响 **CSS 变量的继承**，子组件天然拿得到。App.vue `.page` 与 AccelView `.gh-accel` 里的同名令牌定义已删，**改配色只改 main.css 一处**。
  - **通用控件类：布局骨架类已上提全局，业务类仍自带**：`.btn-row`（按钮行）与 `.link-btn`（下划线文字链）已收进 `main.css` 作全页单一来源（全局规则不参与 scoped 哈希，子组件直接生效）；`.card` / `.field` / `.label` / `.msg` / `.hint` / `.guide` / `.fold` / `.ver` 这类仍是父级 scoped 样式，子组件用到的部分需自带（选择器带哈希，父组件规则匹配不上子组件非根元素）。
  - **根节点必须是稳定元素**：`vue-tsc` 会把 `<template>` 根当 props 校验目标，多根 / 条件根都会出问题；scoped 样式也需要固定宿主节点挂 CSS 变量。故 view 模板统一是 `<div class="xxx">` 外壳，**显隐的 `v-if` 留在父级的组件标签上**，不把「当前 Tab 判断」塞进子组件根节点。
  - **抽走后父级的引用要一并清**：`refreshGhAccel()` 原在 `onMounted` 预读一次，抽出后由组件自己在切到对应 Tab 时刷新（组件内 `watch(() => props.activeTab, ...)`），父级那句要删，否则 `TS2304`。同理，只被搬走代码用到的类型 import 也要从 `App.vue` 删掉（`GhAccelOpLog` / `GhAccelTrace` / `GhAccelVerifyResult`）。
- `public/preload/package.json` = `{"type":"commonjs"}`：项目根为 ESM，此文件保证 `preload/` 及 `preload/lib/` 下的 `.js` 一律按 CommonJS 解析。

> preload 遵循 uTools 规范：CommonJS、可 `require('electron')`、**不得压缩/混淆/打包**；因此拆分的 `lib/*.js` 必须以 `require('./xxx')` 方式在包内相对引用。
