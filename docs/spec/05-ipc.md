## 五、IPC 通道契约

| 方向 | 通道 | payload | 说明 |
|---|---|---|---|
| 子→父 | `whale:ready` | — | 悬浮窗 DOM/preload 就绪，请求初始数据 |
| 子→父 | `whale:refresh` | `{manual?:boolean}` | 请求余额（25s 缓存 + in-flight 去重） |
| 子→父 | `whale:config` | config patch | 改大小/音效开关/音色/音量/**透明度**/用量/峰谷/气泡/报时/置顶/避让任务栏与贴边间距/吸附开关与吸附区宽度；`{__live:true}` = 拖动中实时预览（只改窗口几何 / 透明度，不写存储、不回推设置页） |
| 子→父 | `whale:drag-begin` | — | 开始拖拽：宿主进入「拖拽冻结」态（期间缩放请求只记最后一个目标值，不改尺寸）并作废几何缓存。页面在 pointerdown 命中鲸鱼时立即上报，不能等首次 `drag-move`：按下到首次移动之间若来一次滚轮 / 实时缩放，尺寸会先被改 |
| 子→父 | `whale:drag-move` | `{x,y}`（目标窗口左上角，屏幕 DIP） | 拖拽中页面按 rAF 节流上报（每帧最多一发）。宿主**只记最新目标**，`setPosition` 由自驱循环（`startDragLoop`，~120Hz）执行：页面不等回执、同帧多次上报天然合并。**别退回「发一帧等 ack」的串行背压**：吞吐被单个 IPC 往返锁死，画圈时每帧都不同、无可合并帧 |
| 子→父 | `whale:drag-end` | — | 松手，主窗解冻（冻结的缩放目标在此补做并持久化）+ 吸附 + 回推 snapped。**点击路径与 pointercancel 也必须上报**：只点击不拖动也走这里解冻，否则宿主停在冻结态，之后滚轮缩放全失效 |
| 子→父 | `whale:ignore-mouse` | `{ignore:boolean}` | 点击穿透开关 |
| 子→父 | `whale:probe-cursor` | — | 问一次「光标现在在哪」，答复走本地推送 `whale:cursor`（父→子 `{x,y}` 相对窗口左上角；拿不到为 `null`）。**为什么需要**：窗口平时是 `ignoreMouse`（不挡下层应用），靠 `pointermove` 建立悬停才临时接管；指针若本来就停在鲸鱼上（页面刚重建 / 挂件刚被拖到光标下），没有 `pointermove` → 悬停永远建立不起来 → 第一下点击被穿透丢掉。页面启动后 350ms 探一次（`document.hidden` 为真时跳过，恢复可见由 `visibilitychange` 补问），用回包坐标补 `hoverAt()` |
| 子→父 | `whale:randimg` | `{id}` | 向宿主单张要一张共享角色**本体**（`id` 来自 `whale:shared-skins` 清单），答复走本地推送 `whale:randimg-data`。形态照抄 `whale:probe-cursor`。**为什么按需要而不是整池推送**：整池实测 39MB 原图 / 52MB base64，一次搬会把读盘 + 编码 + 跨进程克隆全压在「打开挂件」那一下，还要两个进程各常驻一份。宿主侧 `skins.getSharedImage(id)` 单张读盘、**不缓存本体**（缓存了就等于把整池一点点攒回来）；`id` 先过 `ID_RE` 白名单再拼路径，`../` 之类直接回空串。窗口已销毁（`winAlive()` 为假）时直接丢弃，不回包 |
| 子→父 | `whale:widget-visibility` | `{hidden:boolean}` | 页面可见态上报：悬浮窗 preload 在初始 / `visibilitychange` / `pageshow` / `pagehide` 时推 `document.hidden`。宿主 `watchTick` 据此在挂件不可见（最小化 / 显示桌面 / 切虚拟桌面 / 被连带 hide）时跳过任务栏轮询里的 `utools.getCursorScreenPoint()` —— 隐藏态取光标只会拿到过期值并可能误触发重摆。**为什么不能只靠原生信号**：`isVisible()` / `isMinimized()` 只反映窗口自身显隐，Windows 上切虚拟桌面 / 显示桌面时 `isVisible()` 不一定翻 false，页面级不可见由 `document.hidden` 兜住 |
| 子→父 | `whale:remind-tick` | — | 到点扫描的**第二路驱动**：挂件窗可见时每 30s 上报一次，宿主收到后跑同一套 `reminders.runDueTick()`。**为什么需要**：主窗（设置窗）关闭后会被隐藏，它的 30s 表被 Chromium 后台节流成 60s（真机日志实测：`onPluginOut(isKill:false)` 后约 2 分钟，间隔从 30.000s 变 60.000s）；挂件窗常驻桌面且可见，渲染进程不被节流，用它补拍。挂件不可见（最小化 / 显示桌面 / 切虚拟桌面）时页面**主动停发**，回落到主窗兜底表；挂件未创建 / 已销毁时天然没有这条。宿主只认当前挂件窗口（`event.senderId` 与 `getWindow().webContents.id` 比对，重载 / 重建期间的旧页面不叠加成双倍节奏），并与主窗表共用 `lib/remind-tick.js` 的 20s 去抖（2/3 周期），同一秒只跑一次、两路同时健康也最多 20s 一拍 |
| 子→父 | `whale:input-focus` | `{focus:boolean}` | 菜单输入焦点：`true` = 挂件窗口 `focus()` 借焦点（窗口 `focusable:false`，键盘事件进不来，倒计时时/分/秒、定时刻输入框打不了字）；`false` = 关菜单时交还，宿主 `utools.showMainWindow()` 唤回主窗，避免设置窗失焦自动隐藏 |
| 子→父 | `whale:open-settings` | `{ target?: string }` | 挂件菜单唤出主窗（`utools.showMainWindow()`），「只显示挂件」模式的设置入口。**可带 `target`**：宿主唤窗后调 `settings.emitNavigate(target)`，设置页 `applyNavigate(target)` 切 Tab 并展开相关卡（`services.onNavigate` 订阅）。无载荷 = 默认 Tab；redirect 分支（主窗不存在、需 `utools.redirect`）页面全新加载，target 投递不到 |
| 子→父 | `whale:hide-widget` | — | 挂件菜单「隐藏挂件」：宿主 `destroyWidget()` 销毁悬浮窗（与设置页同一路径），下次「显示挂件」重建并加载最新页面 |
| 子→父 | `whale:timer` | 计时状态对象，或 `null`（清除） | 计时开始 / 停止 / 到点时落库，宿主重建挂件后回推恢复 |
| 子→父 | `whale:timer-done` | `{text}` | 计时到点：发不发由页面按 `timerNotifyOn \|\| (timerMailOn && notifyMailOn)` 判断（只开邮件也发）；收到即走统一出口 `notify(text, readConfig())`，按配置发系统通知 / 邮件 |
| 子→父 | `whale:focus` | `{mode,startAt,endAt,minutes,isBreak,abandoned}` | 挂件把**跑完或放弃的那一段计时**报上来：`mode` = `down`/`up`/`at`，`isBreak` = 是否休息轮，`abandoned` = 中途放弃。**页面只描述事实，什么算一轮、归哪天、天表怎么聚全在宿主**（`lib/focus.js` 的 `isRound` / `deriveDays` 是唯一口径）。门控在页面侧：`focusOn` 开着才报，一轮只报一次（持久化的 `reported` 位，到点后重置 / 重载补弹都不会重复记账）；放弃且不足 1 分钟不报（没进入状态）；**被打断的休息不报**（说明不了任何事，只往日志倒噪音），走完的休息报一条、带 `isBreak`。宿主侧：先读待办快照（当前 `focusId` 对应条目）→ `appendSession`（`d` 取结束那一刻，`todoText` 是**完成时快照**，任务之后改名/删除仍可读）→ `pruneFocus(FOCUS_KEEP_DAYS)` → `writeFocus` → `syncTodoRounds()` 按会话回填待办轮数（**不再 `rounds+1`**，写失败不假报、不推快照）→ 今日轮数首次跨过目标时 `notifyDaily(kind:'goal')` → `emitFocusChange()` + `pushFocusStats()`。**刻意不搭 `whale:timer-done` 顺风车**：那条被通知开关门控，专注统计不该受通知偏好影响 |
| 子→父 | `whale:todo` | `{op:'toggle'\|'focus'\|'unfocus'\|'add'\|'clearDone', id?, text?}` | 挂件待办区的轻操作（**与父→子同名通道方向相反**，两窗口各注册 `ipcRenderer.on`，互不干扰）。`op` 只认这几个值，其余丢弃；`toggle` / `focus` / `unfocus` 必须有 `id`；`toggle` 取反 `done`（完成时若 `focusId === id` 一并清空专注标记）；`focus` 做 `focusId = focusId === id ? '' : id`（再点即取消，**已完成的不给设专注**）；`unfocus` 清空指向该条的专注标记（`focusId === id` 时置空，页面「不计时」条目再点一次走这条）；`add` 用 `text` 新增一条（折叠空白 + trim + 截断到 `TODO_TEXT_MAX`(60)，空则丢弃；已达 `TODO_MAX`(200) 不再新增），插入最前；`clearDone` 清掉所有已完成项，并把指向已删条目的 `focusId` 置空。到点提醒只从设置页 `todoSetDue` 改（挂件侧历史上那条 `op:'due'` 已无生产端，删除以免两套写法漂移）。写 `whale:todo` 成功后重推 `pushTodo()` + 广播 `emitTodoChange()`；写失败直接返回，不假报 |
| 子→父 | `whale:page-log` | `{msg, detail}` | 页面侧 `logErr` 只能打 console，打包版无 DevTools 取不到，转交宿主写进 `%TEMP%\whale-debug.log`（`msg`/`detail` 各截断 500 字符） |
| 子→父 | `whale:dsh` | `{action:'status'\|'start'\|'stop'\|'restart'\|'update'\|'versions'\|'open'}` | dsh 控制：宿主先探测端口（`config.dshPort`，默认 3080；识别外部终端跑的 dsh）再执行，结果同通道回推 |
| 子→父 | `whale:models-refresh` | `{ids?:string[]\|null, force?:boolean}` | 多厂商模型余额/额度刷新：`ids` 省略 = 全部；`force=false` 时距上次不足 `MODEL_STALE_MS`(5min) 跳过（菜单懒加载，反复开不一直打网络）。宿主先推一次现有快照（菜单立刻显示上次结果），收尾（成功或失败）再推一次并带 `refreshDone:true`：「刷新全部」据此解锁，不靠定时器猜耗时 |
| 子→父 | `whale:set-main-model` | `{id}` | 挂件菜单点某行 = 设为挂件主显示。宿主 `patchConfig({mainModelId})` → 推 `whale:models` → `emitConfigChange()` 反向同步设置页单选（否则两处不一致） |
| 父→子 | `whale:init` | `{config, anchor:{hAnchor,vAnchor,flipped}, space:{up,down}, balance, timer, sounds, skin, bubbles, models, todo, todoMax, focusStats}` | 初始化；`todo` = 待办快照 `{items,focusId}`（**仅 `todoOn` 开启时有值，关闭为 `null`**，挂件据此整组隐藏）；`todoMax` = 待办条数上限（`constants.js` 的 `TODO_MAX`，**恒有值**）：页面在快速添加前先判一次，满额时给气泡并保留输入内容 —— 宿主的 `whale:todo` add 在满额时是静默丢弃的；`focusStats` = `{summary, goal}`（**仅 `focusOn` 开启时有值，关闭为 `null`**，与 `whale:focus-stats` 同形，见该行）；`space` = 挂件本体到工作区上/下边缘的空白 px（窗口不存在为 `null`），页面据此决定菜单展开方向（见第四节）；`timer` 仅在 `timerPersistOn` 开启时有值；`sounds` = 六槽位 base64 data URL 数组（每槽位至多一段；未导入为空数组）；`skin` = 自定义形象 base64 data URL（未导入为空串）；`bubbles` = 气泡图 base64 数组（未导入为空数组，回退内置 `rua.webp`）。**一个窗口只推一次**：来源可能是子窗 `whale:ready`，也可能是创建后的 300ms 兜底（ready 丢失时），两者互相撤销 —— `pushInit` 清掉兜底句柄，晚到的创建回调凭 `initPushed` 不再排兜底（真机时序里回调可比 ready 晚 400ms）。页面自身重新加载会再发一次 ready，那次照常推（不能按「已推过」直接吞） |
| 父→子 | `whale:show` | — | **首帧就绪后显示悬浮窗**。窗口以 `show:false` 创建（见第八节），`whale:ready` 后宿主推初始数据、待首帧绘制完成再 `show()`，避免加载瞬间露出内置形象/空白首帧。另有 `WIDGET_AUTOSHOW_MS` 兜底：页面迟迟不就绪（异常/被脚本阻塞）时强制显示。`resetWidgetShown()`（随 `destroyWidget` 调）清掉会话内「已显示」去重标志，重建后可再触发 |
| 父→子 | `whale:balance` | 余额 payload（见下） | 余额/今日已用结果 |
| 父→子 | `whale:config` | 完整 config，或 `{opacity}`（实时预览） | 设置页/菜单改动广播 |
| 父→子 | `whale:todo` | 待办快照 `{items:[{id,text,done,at,doneAt,est,rounds,tm,mins,remindOn,remindKind,remindAt,remindDow,remindedFor,notifiedFor}], focusId}` | **整份覆盖**（页面直接替换 `todoState`，不增量合并）。`est` = 预估番茄轮数、`rounds` = 实际完成轮数（**由会话明细派生**：`store.syncTodoRounds()` 用 `focus.roundsByTodo` 回填，只数 `isRound` 合格的轮，不再由各次上报 `+1`）；`tm` = 这条自己的计时方式（`'down'` 倒计时 / `'up'` 正计时 / `''` 不计时，缺省 `'down'`）、`mins` = 倒计时分钟数（1–600，缺省 25）—— 挂件点该条的「开始」就按这套参数启动计时；`remindOn` / `remindKind` / `remindAt` / `remindDow` = 到点提醒字段（口径见设置页 `todoSetDue` 与 `reminders.normRemind`；缺省归一为「无提醒」，挂件只读画徽标）；`remindedFor` = **挂件气泡已展示**到的到点时刻、`notifiedFor` = **系统通知/邮件已处理**的到点时刻（两套幂等位，老数据只有 `remindedFor` 时按它回填 `notifiedFor`）。触发点：设置页增删改后（`todoMutate` → `pushTodo()`）、挂件勾选 / 切专注 / 新增 / 清已完成后（写盘成功回推）、`whale:focus` 记账后（回填成功才推）、`todoOn` 翻转时（`patchConfig` 补推，否则后开待办的用户没快照可画）、恢复备份 / 清除数据后 |
| 子→父 | `whale:todo-due-ack` | `{id, dueAt, shown, debug?}` | 到点提醒气泡回执（配合 `whale:cmd` 的 `todo-due`）。宿主每 30s 扫一次（**两路驱动**：主窗表 `services.js` 插件进入时启动并立即补扫一次，**只有 `isKill=true` 真退出才停表**（隐藏 / 后台驻留 `isKill=false` 时不停；关闭已分离的设置窗属 `isKill=true`，插件与挂件都会结束）；挂件窗可见时经 `whale:remind-tick` 每 30s 补一拍，两路共用 `lib/remind-tick.js` 的 20s 去抖）→ `reminders.runDueTick()` 取「未完成、已到点、且 `dueAt > notifiedFor` 或 `dueAt > remindedFor`」的条 → **两套幂等位分开记账**：`notifiedFor`（系统通知/邮件已处理）按 `notify()` 返回的 `{system, mail}` 实际送达才写，**发过就不再重发**；`remindedFor`（挂件气泡已真正展示）只由本回执 `shown:true` 才写，被计时气泡拦住回 `shown:false` 时不动，**下个 tick 继续补弹**。气泡一旦展示，通知位也一并前进（避免免打扰结束后再补发一条迟到通知）。免打扰时段（`inQuietHours`）只压系统通知/邮件，气泡照弹；`todo-due` 里页面只弹一次非 force 提醒气泡。`once` 型只要两套位还有一套没写就一直是 due，**不会永久丢**。`debug:true` = 设置页调试入口「立即触发提醒」的演练回执，宿主跳过记账。`dueAt` = 本次命中的到点时刻（ms），`text` = 条目文案。**只提醒，不自动开始计时、不改清单**；窗口不在 / 页面未就绪时气泡收不到，等下个 tick 重投 |
| 父→子 | `whale:focus-stats` | `{summary, goal}` | 专注统计快照（与 `whale:init` 里那份同形）。`summary` 由 `focus.summarize(readFocus(), todayKey(), 7)` 现算：`{series, today:{r,m}, total:{r,m}, streak, days, todayByTodo}`（`FOCUS_STATS_DAYS` 与 `FocusView.vue` 同值；`todayByTodo` 供待办行显示「今日 N 轮」）；**设置页 FocusView 另外按 90 天窗口直接调 `focusStats(90)` 画热力图 / 对比回顾句**（宿主保留上限 `FOCUS_KEEP_DAYS`），与这条推送的 7 天窗口互不影响；`goal` = `cfg.focusGoal`（0 = 未设）。**触发点**：`whale:focus` 记完一段、设置页改 `focusOn` / `focusGoal`（`settings.saveConfig` 检出变更即 `pushFocusStats()`）、清除数据 / 恢复备份后（不留旧数字在界面上）；页面收到后重画专注统计并 `renderTodoMenu()` 刷新待办行徽标 |
| 父→子 | `whale:cmd` | `{cmd, payload?}` | feature 快捷指令 / 全局快捷键经宿主转发到挂件页。`cmd` ∈ `timer-toggle`（运行中→暂停、暂停→继续、未开始→开始）、`refresh-balance`（页面自己发 `whale:refresh(manual)`，与菜单「刷新余额」同一路径，宿主不直接打网络）、`show-focus`（气泡区显示今日专注摘要，未开启 / 无记录时给引导文案）、`todo-due`（待办到点提醒，`payload = {id, text, dueAt, debug?}`，由待办扫描自动推送，`debug:true` 仅调试入口使用，见 `whale:todo-due-ack`）。**页面未就绪时宿主不丢指令**：`ipc.js` 用 `widgetPageReady`（`whale:ready` 置位）+ 待发队列，同 `cmd` 去重、上限 8 条；窗口销毁重建时 `resetWidgetShown()` 一并复位该标志与队列（旧指令不补发到新窗） |
