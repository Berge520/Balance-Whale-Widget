6. **副本一致性校验**：同一常量在宿主 / 设置页 / 浮动页 / 样式表各留一份副本，消不掉（preload 不参与打包、浮动页无 `require`、CSS 变量宿主读不到），改一处忘另一处就静默不一致（台词 / 提醒文案 / 阈值 / 留白 / 缩放范围两边不同），故 `scripts/check-shared.mjs` 构建前逐对比对，不一致直接失败；**新增同类副本要加进该脚本的 `CHECKS`**。比对项：`PEAK_HOURS`、`MODEL_MONEY_PREFIX`、低余额阈值、`QUOTE_TEXT_DEFAULT`（宿主 `const QUOTE_TEXT_DEFAULT` / 挂件页 `var QUOTES`）、`ALERTS_DEFAULT`、`TOKEN_PRICE_DEFAULT`、`TOKEN_PRICE_MODELS_MAX` ↔ 设置页 `PRICE_MODEL_MAX`、`HISTORY_KEEP_DEFAULT/MIN/MAX` ↔ 设置页 `HISTORY_KEEP`、`WIN_PAD` ↔ `--whale-pad`、`MIN_SCALE` / `MAX_SCALE`、`SCALE_STEPS`、`SOUND_FILES` ↔ 设置页 `BUILTIN_SOUND_SETS`、`DSH_PORT_DEFAULT` ↔ 设置页 `DEFAULT_DSH_PORT`。三处形态不同，另写取值函数：`HISTORY_KEEP`（三个数字常量 vs 一个对象，抽成「默认,下限,上限」）、`BUILTIN_SKINS`（「id → 路径」对象 vs id 数组，抽成排序后 id 集合）、`SOUND_FILES`（对象 vs **带 TS 类型注解**的数组，抽成排序后的 `./whale/*.mp3` 路径集合 —— 取字面量不能取「marker 后第一个括号」，会落在类型注解上，先按 `=` 定位再配平）。`SCALE_STEPS` 是三处同值副本（`constants.js` / `floating-page.js` / `App.vue`）且已进 `CHECKS`；但「整数档 ↔ 倍率」的换算公式（`(MAX_SCALE - MIN_SCALE) / (SCALE_STEPS - 1)`）是表达式而非字面量，比对不到，改范围要连设置页与挂件页两处公式一起看。

8. **持续集成**：`.github/workflows/ci.yml` 在 push 到 `main` / PR / 手动触发时依次跑 `npm run lint` → `npm run typecheck` → `npm test` → `npm run build`（Node 24 + `npm ci`），与本地四关**完全一致**，不额外引入工具链；`dist/` 不上传、不发布，CI 只拦编译不过 / 类型错 / 单测挂 / 副本校验失败。
9. **发版自动化**：`.github/workflows/release.yml` 由 **tag 触发**（`v*`）；tag 与 `package.json.version` 对不上（`GITHUB_REF_NAME#v` ≠ `package.json.version`）直接失败，免得 Release 产物与版本号各说各话。随后跑与 CI **同一套** `lint → typecheck → test → build`（`fetch-depth: 0` 供 `--generate-notes` 回溯上一个 tag），把 `dist/` 打成 `balance-whale-widget-<tag>.zip`，再 `node scripts/check-zip-size.mjs <zip>` **校验体积**（上限在 `scripts/zip-limits.mjs`，单一来源；历史事故：`dist/resources/` 下废弃的 44MB 素材包被原样打进包，而四关全绿、Release 照发），最后 `gh release create --generate-notes` 建 Release（变更说明由 GitHub 按 commit / PR 生成；README「版本记录」仍是人工对外口径）。CI 侧只查体积，不跑 `verify-release-zip.mjs`（它依赖 `gh release download` 与本地补传的 `skins-pack.whaleassets`，CI 拿不到）；完整资产核对由 `release.mjs` 在本地收尾时执行，两处共用同一体积上限。**边界**：uTools 市场仍需人工打包 `.upx` 上传，脚本只到「校验版本 → 跑检查 → 构建 → 打包 → 校验体积 → 建 Release」。
