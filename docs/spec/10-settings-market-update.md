  - **⚠️ 检查更新 / 更新插件（`updateState` + `marketCheckUpdates` + `marketUpdate`）**：已装插件在卡片里会显示「v实装 → v目录」与绿色「可更新」徽章，已装分支多一个「更新」按钮，筛选轴多一个「只看可更新」开关。
    - **⚠️ 口径：优先比「实装版本」，拿不到才退回「声明范围」**（`installedVersions` + `realizedVersionBySpec` + `parseVer` / `cmpVer` / `rangeAllows` / `lowerBoundOf` / `updateState`，全部零依赖手写）。判定 `实装 < 目录` 即 **update**，相等算 **current**（重装一遍没意义）。
    - **⚠️ 退回范围判定时按「声明范围的下界」比方向，不能用 `rangeAllows`**（`lowerBoundOf`，真实降级事故）：`rangeAllows` 只答「满不满足范围」，答不了「谁新谁旧」，拿它判方向两个方向都会错。**事故**：实装 `1.62.0`、声明 `^1.62.0`、目录滞后到 `1.61.0`；`rangeAllows('^1.62.0','1.61.0')` 见其低于下界返 false → 判「有更新」，界面显示 `v1.62.0 → v1.61.0` 并给按钮，点下去把用户**降级**。反向也错：`^1.62.0` 容得下 `1.65.1`，返 true → 判「已最新」，漏掉 `^` 范围内的正常小版本升级。**修法**：`lowerBoundOf(range)` 取范围下界（`^1.62.0` → `1.62.0`、`~1.2.3` → `1.2.3`、`>=1.2.0` / 裸版本同理），目录高于下界 → `update`，不高于 → `current`。取不到下界（`*` / `latest` / `workspace:*` / 认不出的形态）才退回 `rangeAllows` 保守口径（返 true 落 `current`，即不报）。
    - **⚠️ 为什么必须改成比实装**：`profile/package.json` 的 `dependencies` 存的是**声明范围**（`^0.5.11`），拿它比只能答「目录版本是否**超出**范围」—— `^0.5.11` 装到 `0.5.13` 时目录出 `0.5.13` 明明该提示，却因为「落在范围内」被判成已最新。实测多数依赖的实装版本恰好等于范围下界（`^0.5.11` 实装就是 `0.5.11`），这类同 minor 内的小版本升级确实算「有新版」。旧口径的「保守」是漏报，不是安全。
    - **⚠️ 展示上 v 前缀只加在确定是版本号的一侧**（`dshMarketVersionText`）：实装版本是裸 `0.5.11`，`v0.5.11 → v0.6.0` 没问题；退回范围时左侧是 `^0.5.11`，硬拼会变成 `v^0.5.11` 这种**语法上不成立**的写法，故那一档显示成「声明 `^0.5.11` → v0.6.0」**不带 v**。`dshMarketUpdateTip` 的悬停说明讲清判定依据（实装 / 范围）。
    - **⚠️ 退回范围判定时**不能**用 `parseVer` 把关**：那里放的是范围字符串，`parseVer('^0.5.11')` 直接返 null，会让每条带 caret 的包都掉进 `unknown`。「范围能不能认」交给 `rangeAllows` 自己判，它认不出的形态（`workspace:*` / `npm:` 别名 / `latest`）返 true 落到 `current`。**⚠️ `rangeAllows` 只负责这一档「认不认得出」的兜底，不负责判方向** —— 方向交给上一条的 `lowerBoundOf`；只有取不到下界时才用它的返值决定 current / update。`updateState` 返回值带 `basis: 'realized' | 'range' | 'none'` 标明本条的判定依据，界面据此选文案。
    - **⚠️ 更新前 / 更新后都要重读实装版本**（`realizedOf`）：`marketUpdate` 的 `from` 只取实装版本，**不退回** `hit.depVersion`（否则又会拼出 `v^0.5.11`）；更新成功后重新调 `realizedOf` 取新版本作为 `to`，不能缓存旧值。
    - **⚠️ 0.x 的 caret 上界是下一个 minor**（`^0.5.11` → `[0.5.11, 0.6.0)`），tilde 的上界是 **同一个 minor 的下一个**（`~1.2.3` → `[…, 1.3.0)`；只有 `~1` 这种缺 minor 的才升 major）。两者都容易写错成「升 major」，单测各钉一组边界。
    - **目录没给 `version` 就只能是 `unknown`**：目录里近半条目（github / tarball 来源）没有 `version`，比不了。界面**只认 `state === 'update'`**（`dshMarketHasUpdate`），`unknown` **不出徽章、不进计数** —— 不能把「不知道」画成「有新版」。
    - **⚠️「更新」= 按目录 spec 重装，不是 `pnpm update`**：`pnpm update` 只在**声明范围内**升（升不到 0.6.0），而「有更新」的定义正是**超出声明范围** —— 用 `pnpm update` 永远更不到。重装会让 pnpm 把 `package.json` 里的范围**改写**成新版本的写法，这恰是用户期望的「升到市场里那个版本」。
    - **⚠️ 更新与安装走同一条链路**（快照 → `pnpm add` → 回读核验），只是 `reason` 用 `before-market-update`、文案不同。更新失败同样要能回滚。
    - **⚠️ 更新不走「先卸载再安装」**：卸载会先删包，一旦重装失败就留下一个**空环境**；`pnpm add` 同一个包是幂等覆盖，失败时旧版本还在。
    - **⚠️ `marketCheckUpdates` 要目录数据，所以生命周期与 `marketStatus` 不同**：`marketStatus` 是**纯本地**的（展开卡片就读），而「有没有新版」需要目录。故 `catalog` 由界面把**已经拿到的目录原样传回**（`dshMarketCheckUpdates({profile, catalog})`），宿主**不自己联网** —— 否则就绕过了「默认零网络请求」。界面只在 `dshMarketLoad` 与 `dshMarketRefreshStatus` 成功后重算。
  - **装载 / 卸载走三段式**（`dryRun 预览 → 用户过目 → 确认`），与「一键隔离」同一套交互：`dshMarketPreviewInstall` / `dshMarketPreviewUninstall` 先调宿主拿计划（**这三个 API 返回 Promise，必须 `Promise.resolve(...).then(...)` 取结果**），用户看过计划再点「确认」才落笔。确认前宿主**强制建快照**（`dshBackup.createSnapshot`，reason 分 `before-market-install` / `before-market-uninstall` / `before-market-disable`），做完**回读磁盘核验**。
  - **卸载有两种语义，界面都要给**：① **只禁用、留包**（往 patch 追加 `- id: X` + `disabled: true`，包仍在磁盘上）—— 走 `dshMarketUninstall({remove: false})`；② **彻底删除**（从 profile 卸包）—— 走 `dshMarketUninstall({remove: true})`，**二次确认**。**⚠️ `patchReload` 是单向的**：加 `disabled` 即时生效，**删掉不恢复** —— 所以「启用」必须重启 dsh，界面给「已禁用」的条目一个重启提示。
  - **⚠️ `dshMarketUninstall` 可选带 `id`（dryRun 算出的 patch 条目 id），真写要把它带回来**：禁用分支写的 id 由「用户当前 patch 里那条的名字」决定（可能是去掉 scope 的短名，`shortName`），dryRun 阶段算一次、界面存进 `dshMarketPlan.id`。但两者是**两次独立调用**，真写没有 dryRun 的 `status` 可依据；若照旧自己重算，一旦用户两步之间改过 patch，写入的 id 就可能与单据上看到的不是同一个 —— **写错 id 等于往 dsh 里塞一条死条目**（`patch: entry "X" not found`，退出码仍 0，见上条）。故真写优先用 `o.id`，反查只在没有它时才做。类型侧 `dshMarketUninstall` 入参加 `id?: string`。
  - **⚠️ `dshMarketUpdate` 真写必须带 `npm`（npm 名），否则只能退回比声明范围**：宿主的 `o.npm` **只作核验用**（走 `validPkgName` 过闸；命令仍按 `spec` 拼）。不带它，`marketUpdate` 判「实装是否落后」时只能退回比**声明范围**，而 `^1.48.0` 是容得下 `1.49.0` 的 —— 会出现「dryRun 单据说能更新、真写说无需更新」的自相矛盾（与 `dshMarketInstall` 早先的同一个坑，见上）。界面侧 `dshMarketConfirm` 的 update 分支因此传 `npm: plan.npmName`，`npmName` 由 `dshMarketPreviewInstall` / `dshMarketPreviewUpdate` 在 dryRun 阶段回填（取 `p.npm`）。
