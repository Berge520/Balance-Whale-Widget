    - **⚠️ 配置端口 ≠ 运行端口：`state.port` 与 `state.runPort` 必须分开存**（2026-09-26 修：运行中改端口会误显示「启动中…（新端口未就绪）」）。根因：`configure()` 换端口时无条件把 `state.ready` 置 false，而 `state.child`（旧进程）仍活着 → `snapshot()` 出现 `running=true + ready=false` 这个**本来不存在**的组合 → 前端按「新端口启动中」渲染。**`ready` / `readyAt` 描述的是 `runPort`（进程实际监听的那个端口）上的事实**，不是配置端口上「该不该就绪」的期望：
      - `state.runPort` = 本次 `start()` 真正监听的端口（`start()` 里记 `= state.port`，两处进程退出清理归零）。`configure()` 改端口时**按「进程是否活着」分流**：没有 `state.child` 才把 `ready`/`readyAt`/`runPort` 归零；有进程在跑则**保持 `ready`/`readyAt` 不动**（旧进程没停，旧端口「已就绪」仍成立）。
      - `snapshot()` 暴露 `runPort`（`state.child ? state.runPort : 0`）与 `needsPortRestart`（`!!state.child && state.runPort > 0 && state.runPort !== state.port`）。**判据用 `runPort > 0` 而不是 `!!runPort`**：端口是数字，运行端口为 0（尚未写入 / 旧快照）时不提示，免得把「尚未记录」误报成「需重启」。
      - 前端 `dshStateText` 在 `dsh.running` 分支里**先判 `needsPortRestart` 再判 `!ready`**：前者为真时输出「运行中 · pid N · 端口已改为 X（现监听 Y），点『重启』生效」，**绝不**落进「启动中…（X 未就绪）」那一支；`dshSetPort()` 的运行中提示同步按「当前进程仍在 Y 上运行」措辞（说「重启后生效」会让人以为端口已切一半）。挂件 `floating-page.js` 的 `dshRender()` 状态行与 title 同步。
      - 单测 `test/dsh-port-change.test.mjs`锁死这条语义，核心断言是 **`!(running && !ready)` 这个组合永不允许出现**。测试必须走真实路径 `syncConfig → readConfig() → configure()`（挂假 `whale:config` 存储 + `readConfig()`，而非直接喂半份配置），并借 `dsh.js` 为单测导出的 `__state` / `__probe` / `readConfig` 直接摆状态。
    - **⚠️ 外部 dsh 也要有「运行端口」留档：`state.extRunPort` / `extRunPid` / `extRunName`**（2026-09-26 修，用户报外部 dsh 改端口后直接变『未运行』，而旧端口还在跑）。这是上一条的**另一半**：它管别的终端启的 dsh，不在 `state.child` 里，而 `configure()` 的「有进程在跑就保持」只看 child，漏掉了它。根因：`external`/`portOther` 全从 `probe` 派生，而 `probe` 是**单例且只描述当前配置端口**（换端口必须清空重探，否则快照自相矛盾）；清空后 `externalPid()` 恒返回 0 → 界面落到「未运行」，「结束」「重启」按钮一并禁用（按 `!running && !external` 判），**用户连那个还在跑的进程都结束不掉**：
      - `configure()` 端口变更时**在改写 `state.port` 之前**调 `externalPid()`，把已确认的外部进程搬进 `extRun*`（端口记旧配置端口）；两个都没有（无 child、无外部）时才清空留档。`probe` 照旧清空重探 —— 清 probe 是对的，缺的是留档。
      - `snapshot()` 的 `external` / `externalPid` / `externalName` 判据**含留档**，并新增 `externalRunPort`（`extRunPid > 0 ? extRunPort : 0`）供界面说清现监听端口；`needsPortRestart` 也把外部留档并进判定（`|| (extRunPid > 0 && extRunPort > 0 && extRunPort !== port)`）。
      - **留档的存活校验**：留档只在「它 ≠ 配置端口」时有效（能探到就用 probe，无需留档）。`snapshot()` 里用 `pidAliveState(extRunPid) === 'dead'` 判活，确证已死就清掉留档 —— 否则外部进程在别处 Ctrl+C 后会永远误报「外部 dsh 在跑」。`unknown`（查不准）时**保守保留**。
      - **「结束」与「重启」要认得留档**：`stop()` 在无 child 时先看 `externalPid()`，为 0 再看 `extRunPid` —— 后者走 `stopExternal(pid, done, extRunPort)`。`stopExternal` 新增 `runPort` 参数决定复查口径：**目标端口 == 配置端口**时照旧探端口（最可靠），**≠ 时只能按 pid 判活**（`probePort` 探的是新端口，必然「一开始就空」，会把还在的进程误判成「已结束」）。`restart()` 的「要先结束」判据同样含 `extRunPid`，否则改端口后点重启会**跳过结束直接 start**，旧端口实例没停、两个 dsh 并存（期望「重启」＝结束旧进程再在新端口启动）。
      - 前端：`dshStateText` 的 `dsh.external` 分支在 `externalRunPort !== dsh.port` 时输出「外部 dsh · pid N（现监听 Y）· 端口已改为 X，点『重启』生效」；`dshSetPort()` 新增 `dsh.external` 分支（说「外部 dsh（pid N）仍在 Y 上运行」）；挂件 `dshRender()` 状态行与 title 同步。
  - **状态轮询只在「开发者」Tab 激活时进行**（`watch(activeTab)` → `dshPolling.start()/stop()`）：dsh 是低频开发功能，停在其它 Tab 不空转；首次进入补一次 deep 探测（识别外部终端里跑的 dsh），轮询本身为**浅探测**（`dshStatus(false)`，不触发宿主异步探端口的 600ms 补读）。`onWindowActive` 也只在 dev Tab 下补 deep。初次 deep 探测的时机因此从 `onMounted` 挪到「首次切到 dev Tab」（`dshDeepOnce`）。
